# 正式回放时间笔记与本地 BAR 衔接

依据：[原始需求 #166](https://github.com/helenananaa/CandleScope/issues/166)、[#179](https://github.com/helenananaa/CandleScope/issues/179)、[#181](https://github.com/helenananaa/CandleScope/issues/181)。核对基线 main 395007ac。本文件是下一阶段实现约束与验证入口，不是功能交付或验收记录。

## 复用边界

- 正式入口沿用前端 `managedReplayTransport` / MarketDataManager 和后端 `DataManagerCore.replay`。TrainingRunService/TrainingReviewService 负责应用协调；持久化复用 TrainingRunStore 的 `ReplaySQLiteStore.run_extension_read/write`，不另建账户、不将笔记写入行情缓存。
- 前端复用通用 `JournalEditor` 的草稿、排队保存、client ID 与乐观版本能力。`StudyNoteEditor` 是现成的无账户接入例子；研究笔记当前始终标为补记，其“取最新版本”不能直接成为正式回放原始计划的历史查询。
- 既有 adapter `ADD_JOURNAL_NOTE` 是附着 actor checkpoint 的追加日志，并且 seek 拒绝越过已存日志。新可编辑时间笔记作为独立注释持久化，不以改写既有 actor 日志或账本实现，不默默取消旧恢复检查。
- 既有 `record_review_marker` 为账户/actor 锚点建立复盘事件。普通文本保存不需要冻结金融检查点，不调用撮合或推进事件；不能将每次自动保存都转成账户 mutation。

## 时间与版本

保存必须在运行协调的 serialized 边界读取已提交运行/轨道/数据版本和当前有效视图时间，并在同一 SQLite 注释事务校验。请求带预期笔记版本及视图/运行上下文，旧异步编辑不得借用新运行的时钟。原始计划版本记录生效虚拟时间和实际写入时间；历史查询仅交付查询游标当时有效的版本。历史版本缺失时显示缺失，不用最新文本代替。

回退或 ReviewMode 下的补写单独标为补记，保留实际写入时间和关联市场时间，不覆写原始计划或风险字段。补记按关联时间显示；补记的新版本仍须明确属于后写的复盘内容。运行 live 时钟与 ReviewMode 视图游标不能混用；盲时钟沿用既有 public-time 投影，不绕过披露政策。第一阶段应先明确并覆盖这两个上下文，再开放 UI 编辑。

关联轨道/商品/可选交易和截图需在所属运行内验证。截图绑定保存时已揭示图表和笔记版本，查询旧版本不能返回未来截图、交易详情或未来标签。分页、文本、版本、图片及总存储预算保持有界。保存响应丢失支持相同 client ID/预期版本的权威恢复，另一个窗口的并发编辑显式冲突，失败时草稿保留。

## 首批验收用例

| 场景 | 必须观察的结果 |
|---|---|
| 尚未交易时保存计划，再推进后修改 | 回退显示旧文本及旧关联，未来修改不可见 |
| 后退补写与补写后再前进 | 补记标识/实际保存时间保留，原计划和风险基准不变 |
| 两运行、两轨道、相同商品周期 | 笔记、编辑草稿、版本和截图各自隔离 |
| 保存与快进并发，或保存响应丢失后重试 | 上下文显式校验；不把笔记放到新的时刻；无重复记录 |
| 两窗口并发保存 | 一个提交，另一个冲突并保留草稿，不静默丢失文字 |
| 完全退出与新进程重启 | 注释、各版本与关联可恢复；游标、订单、成交、余额保持原值 |
| ReviewMode / 盲时间 / 迟到请求 | 只按当前有效视图和披露规则返回，迟到结果不覆盖其他上下文 |
| 缺失/损坏版本或达到预算 | 明确错误/缺失与草稿保留，不回退到未来内容 |

源码/组件、真实 HTTP、原生保存/完全退出/重启分开记录；本地 macOS 结果不代替 Windows 或整个 #166。

## 用户导入 BAR 的下一步

先复用 `LocalDatasetService.import_csv` 的版本、时区/时间单位、重复/乱序/缺口和 OHLC 校验及现有资料库 UI。正式回放按固定 dataset ID + epoch + 区间绑定，默认禁止联网补齐及同名在线商品回退；沿用现有 BAR 引擎，不将 K 线伪造成成交路径。开盘时标的完整行只能在其收盘已揭示后交付完整 OHLC；形成中高周期仅使用截止虚拟时间的已揭示细数据。加载完整文件不等于允许预热/指标/账户读取未来。先交付 BAR 全流程，再单独承接市场成交导入及其事件顺序契约。
