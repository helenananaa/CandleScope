# 图表常驻策略执行拆分

依据当前开放#157/#158/#165。基线main e71bbf33；#238是独立正式回放笔记子范围，不把正式回放引擎当成策略执行器。main已有图表挂载身份/草稿、研究移交、固定快照策略、双Manager及提交唤醒；这些不等于持续策略。

首个实现闭合BAR的同一次策略运行恢复，再扩展原生Pine执行语义和外部模型。沿用既有策略Provider、撮合/账户内核及检查点，不能把每次新增数据重新创建整段回测或把模拟账户挂单为空当成跳过策略事件的理由。含实时模式保存实际代码/参数/执行约束，不要求用户管理历史策略版本。首次历史+实时固定初始化截止游标，实时模式从首次启动截止点后开始；恢复均从已提交游标补缺口，不能从前端关闭时间开始。

第一步持久化同一次运行的代码/参数、数据身份、Provider/内核账户/规划器检查点及提交游标，单个事务提交。恢复显式增加代次并拒绝旧写入；纯读取、图表关闭和断开订阅不能推进或取消策略。进度读取不解码完整状态，复用CommittedUpdates唤醒；状态按合理批次和恢复边界保存，禁止逐tick完整序列拷贝/新哈希。有限的检查点与字节预算必须可见报错，保护已有恢复点。

随后把现有BAR执行初始化/每事件执行抽为共享会话，参考固定输入的完整结果验证分批、退出重启与连续参考的信号/订单/成交/权益相同。未处理来源缺口先停止在未就绪状态；处理过的历史修订进入REPAIR_REQUIRED，未授权时保留原结果。修补从有效检查点向后重算，准备好整套策略/账户/游标后原子替换并增加代次；记录扩大范围理由。最后才接两个Manager控制/提交流、三个模式按钮、图表绑定及研究挂回。

当前第一步不是用户可用的实时模式；不得把内部存储/测试算成常驻策略或整个issue已交付。后续原生资格需含保存→完整拥有进程退出→缺口产生→重启，持续新增数据交接、修订确认/自动修补与失败、独立图表/运行、无未来信息，以及独立Windows证据。
