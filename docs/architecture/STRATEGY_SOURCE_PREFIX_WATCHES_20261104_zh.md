# 持续策略的已处理源前缀保护

D126已有按系列合并的变更水位，范围是全系列保守包络，不能当精确逐次事件日志。持续策略不能因正常尾部新增就重算全部历史，也不能仅靠内存BAR_AMENDED事件忽略应用离线期间的SQL修订。保留D126原约定，不增加逐行行情副本/事件日志或重复哈希。

新增有限、按消费者拥有的持久前缀watch：记录完整11字段行情身份、输入from、保护through、incarnation、采集代次、独立内容版本及dirty范围。已有D126 INSERT/UPDATE/DELETE物理触发器在同一事务更新与watch前缀相交的内容版本和dirty标记；尾部追加越过保护through时不影响已提交前缀。上限128个watch，每个只保留一个合并标记，不随行情事件数增长。

采集前使用财务库最后提交的(cursor, source receipt)核对源watch。内容版本晚于该receipt且与已处理范围相交则要求修补，不能普通恢复；只落在尚未提交区间的变化可重新采集。核对并清理已确认标记后，先把保护前缀扩到本批实际截止，再读输入。计算不持有源写锁。

发布前在源SQLite短BEGIN IMMEDIATE内校验incarnation、采集代次和内容版本；固定该源前缀期间提交财务库的策略/账户/游标/source receipt，然后确认watch。Provider快照和编码在进入源写锁前完成。财务提交失败不确认watch；源确认之前崩溃也不会漏掉修订，因为保护through在采集前已持久化，财务receipt保存独立watch内容版本和D126观测水位。恢复以财务库提交点为准，而非source watch的待采集范围。源数据库回退/替换、watch消失或身份变化都必须报未就绪，不能新建一个空watch冒充旧连续性。

所有SQL仍在存储/已有D126物理writer所有者；策略通过DataManager门面使用源保护，不另建行情网络入口。真实SQLite及另一个进程写入、正常追加、旧行插入/修订/删除、回滚、不同商品/语义身份、保护扩展失败、guard期间并发写和双库提交崩溃窗口均须验证。该机制只是源身份/连续性基础，不能替代缺口覆盖证明、修补授权/计算或原生用户模式验收。

watch版本在独立AFTER触发器内增加，不读取“主触发器执行前还是执行后”的globalclock来推测版本，因此不依赖SQLite触发顺序、不多增D126时钟。注册精确重试保留原receipt；普通空前缀不标dirty。采集前确认过的旧提交前缀及其版本另存有限scalar，避免“前次采集未提交但已清除未处理区间dirty”在下一次恢复时丢失证明。

另外保留已确认财务提交的采集代次与through，区分“采集在财务提交前失败”（允许从原点重取）和“财务库回退到已确认进度之前”（拒绝自动接续）。源watch采集代次低于财务receipt同样拒绝。此为有限提交身份，不扫描历史、不建立防篡改哈希。
