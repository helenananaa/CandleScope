# ADR-INDICATOR-001：内置指标数值契约——同一根 K 线只有一个值

- 状态：提议（Proposed）
- 日期：2026-11-11
- 基线：`main@12514a92fb4cc8745e3564538dd68247316e019d`
- 分支：`claude/indicator-seed-consistency-20261111`
- 关联：#161、#170、#155、#164、#154、#120、#169（指标部分）
- 证据：[`backend/tests/test_indicator_seed_consistency.py`](../../backend/tests/test_indicator_seed_consistency.py)（运行 `python -m tests.test_indicator_seed_consistency` 输出分歧表）

## 背景

同一内置指标在同一根 K 线上，不同消费路径使用不同的起算点（种子）：

| 路径 | 起算点 | 代码 |
| --- | --- | --- |
| 图表区间（HTTP / 批量） | 请求起点 − `indicator_warmup_bars`；同一批次共用最大预热 | `app/indicator/warmup.py`、`app/api/v1/indicator_range_batch.py` |
| 实时实例 | 客户端 `historyLimit`，即图表已加载根数（前端上限 2,000） | `app/api/v1/stream_indicators.py` |
| 警报数值 | 最近 250 根 | `app/alerts/indicator_requests.py`、`app/indicator/numeric_queries.py` |
| 本地数据集 | 整个数据集 | `app/local_data/indicator_compute.py` |
| 正式回放 | 固定来源起点，配合检查点 | `app/replay/training/indicator_prefix.py` |

EMA、Wilder 平滑的 RSI/ATR 和 MACD 是递归指标，数值依赖起算点。现行预热按经验倍数设定（RSI/ATR 为 3 倍周期，EMA 为 5 倍周期，MACD 为 5 倍慢线加 3 倍信号线）。在这个预热下，RSI14 的种子残差只衰减到约 4.5%，EMA 约 4.5e-5。区间结果缓存的身份不含起算点，只要覆盖目标区间就会复用。

S1 在生产路径上用模拟 1m 序列测得：

- 图表页首根 RSI14 与收敛值相差中位 0.61、p95 1.94、最大 3.93 点；325 个页起点中有 3 个落在 30/70 另一侧。
- 向左翻页时，前端调度器只请求“期望区间 − 已缓存区间”，旧页起始处欠预热的值不会重算，拼接处出现台阶。
- 图表同时加载 EMA200 会改变 RSI 页首的值。同一请求返回的缓存结果取决于之前的请求顺序。
- 实时 EMA200 按 500 根起算，最新根与历史线相差中位 5.7%、p95 14.5% 个 K 线高度。
- 警报的 RSI、MA20 与图表最新根完全一致；MACD 柱相差约 5e-7。

在常规图表长度下，最新根的值大多已收敛。问题集中在三处：请求起点附近、翻页拼接处，以及长周期 EMA 的实时尾部。

## 决策

### 1. 数值契约

内置指标在 K 线 t 上的值只由以下三项决定：

- 序列身份及其数据修订；
- 指标定义、参数和实现版本；
- t 本身。

它与请求窗口、同批其他指标、缓存命中顺序和客户端已加载根数无关。一致性以传输精度判定：载荷保留 8 位小数，测试容差为 2e-8。

### 2. 机制：由收敛条件推导预热，不为实时路径存检查点

预热根数 W 由平滑系数直接推导，保证种子对 t 的残差权重不超过 1e-12：

| 指标 | W |
| --- | --- |
| EMA(n) | n + ⌈ln(1e-12) / ln((n−1)/(n+1))⌉ |
| RSI(n)、ATR(n)（Wilder） | n + ⌈ln(1e-12) / ln((n−1)/n)⌉ |
| MACD(slow, signal) | 慢线 EMA 与信号线 EMA 两段之和（保守上界） |
| MA、BOLL | period − 1（有限窗口，本身精确） |
| VOL | 0 |

典型值为：EMA20 取 297，EMA200 取 2,964，RSI14 和 ATR14 取 387，MACD(12,26,9) 取 519。参数上限内最大的是 EMA500，为 7,408 根，低于现有 50,000 根的计算上限。

价格在 6 万量级、种子偏差为 10% 时，1e-12 的残差对应误差小于 6e-9，低于传输精度。原型在 8,000 根序列上把 S1 的全部分歧用例降为 0（个别 1e-8 出现在舍入边界）。单次计算耗时 1–3 ms。

不推广回放检查点（原计划 S3）的理由：

- 收敛预热以毫秒级成本就能得到与起点无关的值，图表和实时路径不需要持久状态。
- 实时序列的最早一根会随历史回补前移，以它为锚的值不稳定。回放的来源起点固定，没有这个问题。
- 检查点会带来持久化、失效和回收负担（#121、#156），只有计算昂贵的运行时（Pine、Python）才值得承担。

### 3. 预热只由后端定义

- `app/indicator/warmup.py` 是唯一权威。图表区间、实时种子和警报数值都从它推导。
- 实时实例的种子根数为 max(客户端 `historyLimit`, W + 1)。客户端 `historyLimit` 只决定显示多少输出，不再决定数学起点。
- 警报数值的输入槽为所引用输出中最大的 W + 1，取代固定的 250。
- 前端 `estimateOutputWarmupBars` 只用于显示填充，不再承担数学预热。它还驱动 `resolveHostedSubscriptionSeedHistoryLimit` 的“窗口够长后重新订阅一次”。服务端已强制收敛种子，这一逻辑因此多余但无害。S6 会改为读取后端目录，删除这份重复的表。

### 4. 历史不足时：部分种子

本地数据在 t − W 之前不足 W 根时，按最早一根本地 K 线计算。

初稿要求“部分种子不得用于警报”，核对后这条不成立。日线 EMA200 需要 2,964 天历史，多数品种永远达不到；而从真实上市首根算起的值本身是确定的。需要区分的是：

- **本地已到序列真实起点**（存储报告没有更早的历史）：值以起点为锚，确定，可以用于警报。
- **上游还有更早的历史但尚未下载**：值是临时的。

现有代码已经按这一区分处理：

- 警报：数值捕获在存储还有更早历史（`has_more`）而返回行数不足时，返回 `canonical_history_pending` 并触发预热回补，不会用临时值判定。
- 图表：更早历史落库、回补完成时，桥接层会推进序列修订（`note_correction`）。区间结果和 K 线缓存都以修订为键，会随之失效并重算。因此缓存身份不需要再加入 `fromMs`。

本次补充：内置区间载荷附带 `seed`（`state` 为 `converged` 或 `partial`，另含 `warmupBars`、`seedBars`），缓存诊断新增计数 `partialSeedComputes`。界面提示需要 30 种语言的新文案，留作后续（O3）。

### 5. 三类执行语义

| 类别 | 适用 | 复用规则 |
| --- | --- | --- |
| canonical | 内置指标 | 按序列、定义、参数和实现复用；可用于警报和跨图共享 |
| opaque-script | Pine、Python | 只在输入域完全相同时复用（保持现状） |
| window-relative | 前端 JS | 界面上标明“基于当前窗口 N 根”；不用于警报，不持久化 |

### 6. 回放

- **训练计算**（`indicator_prefix.py`）：以固定来源起点加检查点计算。起点固定，值就确定，因此已满足本契约，不做修改。
- **回放显示**（`indicator_viewport.py`）：本次暂不切换，改用 `replay_display_warmup_bars` 保留原有倍数预算。
  - 原因：回放数据准备按这一预算准备本地上下文（离线时也依赖它）。如果显示改用收敛预热，就会向来源请求本地没有的历史；`test_replay_bounded_context` 中“所需上下文均已在本地”的用例会失败，离线回放可能一直停在 `preparing`。
  - 窗口首次显示后，锚点会持久保存，向左平移不会改写已显示的值，因此回放显示不会出现拼接台阶。但冷窗口左缘仍与窗口有关，见 O4。

## 待决问题

- **O1 缺口语义**：回放遇到缺口会重置递归状态，图表和实时路径则跨缺口连续计算，两者在缺口之后的值不同。本 ADR 不改变任何一方，另行决定。
- **O2 #170 持久化**：内置指标不持久化完整输出（见“后续阶段核对”中的 S9）。是否持久化 Pine/Python 结果，需要单独测量其冷启动成本后再定。
- **O3** 部分种子在界面上如何呈现。载荷已带 `seed`，缺的是图例提示及其 30 种语言的文案。
- **O4 回放显示对齐契约**：需要与回放负责人一起，把数据准备的本地上下文按 `indicator_warmup_bars` 加大，再让 `indicator_viewport.py` 切换过去。同时要评估离线准备的体积与耗时，以及已保存锚点的版本切换。

## 影响

- 图表页首和翻页拼接处的数值会移向收敛值，与全历史计算一致。这也更接近 TradingView 等用长历史计算的平台。需要在发布说明中告知用户。
- 区间请求要多读 K 线：EMA200 的预热从 1,000 根增至 2,964 根，RSI14 从 42 根增至 387 根。
- 没有存量数据需要迁移。

## 验收

- `test_indicator_seed_consistency.py` 中的严格 xfail 全部转为通过，并移除标记。
- 实时种子不随 `historyLimit` 改变数值；警报的 MACD 柱与图表最新根一致。
- 指标、警报和回放的现有测试全部通过。

## 后续阶段核对（S6–S12）

按原计划逐项对照代码后的结论：

- **S6 部分种子**：见第 4 节。已加载荷标记和诊断计数；警报与缓存失效原本已正确。
- **S7 警报引用任意内置指标**：已实施。字段键为 `ind:<名称>:<输出>:<参数>=<值>,...`，只含计算参数（不含颜色），后端按注册表校验并拒绝非规范写法。`rsi`、`macdHist`、`ma20` 保留为别名。单条规则最多 3 个不同指标输出（数值查询上限）。编辑器从注册表列出全部内置输出，并复用指标面板已翻译的参数标签。
- **S8 JS 指标标注窗口语义**：现有代码已满足。编辑器对前端 JS 显示 `indicator.editor.frontendWindow`（只计算图表提供的数据窗口，加载更多历史可能改变结果）；警报字段只接受内置指标，JS 结果不会进入警报。无需改动。
- **S9 #170 持久化**：内置指标单次重算 1–3 ms，所需 K 线已有短期缓存。把完整输出写入 `candlescope.db` 只会给唯一的写连接增加负担（#121），不实施。
- **S10 本地数据集**：本地结果按整个不可变数据集计算，S1 测试已验证与收敛参考一致。原计划依赖已取消的 S3，无需改动。
- **S11 前端指标运行时合并**：规模较大，单独立项，见该提案。
- **S12 计数**：`partialSeedComputes` 已加入区间缓存诊断；现有 `computes`、`hits`、`barsQueries` 等计数可用于性能基线。
