# 回放偶发停顿：2026-09-09 后端与本机连接排查

本轮保留前端通知合并、指标缓存和组件稳定引用的已有改动，继续排查请求侧长尾。以下是开发环境实测，不能视为长期无卡顿验收。

## 已确认的路径与修改

- 共享默认线程池：一次显示投影仅工作约 17ms，却排队 479ms。每个回放数据库现在拥有一个有界线程池（默认 5 个工作线程），供数据库读写、显示投影、关键输入读取使用。实时行情的默认线程池任务不能占用这些工作线程；这不是进程或 GIL 隔离。
- 实时全量盘口：不可变原生档位重复构造 Decimal，懒加载侧反复按索引访问。改为缓存原生档位的精确 Decimal 元组并顺序迭代，保留外部输入验证。每侧 30,000 档的同结果微基准，热运行从约 192–204ms 降到约 65ms；首次运行仍约 182ms，不代表所有盘口场景都有三倍提升。缓存不加入 dataclass 字段，保持序列化、比较、哈希行为。
- 后台交易所目录：临时 asyncio 诊断观察到目录/CCXT 回调占用事件循环约 100–200ms。回放命令现在加入既有前台忙碌/安静期探针，使自动目录刷新避开交互期。已经开始的刷新不会被取消，显式查询仍可执行。
- localhost 建连：一次 430ms 请求的服务端推进与显示合计约 99ms，TCP 建连却花约 316ms。localhost 优先解析到 IPv6，而 Vite 只监听 IPv4。开发/预览服务现在补充同端口的另一回环地址，共用请求与升级处理器，保持浏览器 Origin。不会扩展到公网地址，也不会给 HTTPS 添加明文入口。
- 分阶段诊断：Server-Timing 增加线程排队、工作、线程 CPU、事件循环恢复、数据库串行等待和提交时间，并传播到 actor。Windows 线程 CPU 时钟粒度较粗，零值不等于没有计算；各子阶段可能嵌套，不能全部相加作为总耗时。
