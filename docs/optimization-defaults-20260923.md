# 优化默认启用与回退（2026-09-23）

用户批准在常规启动中启用已经交付的 Replay 逐笔快进，并把行情共享能力与多屏容量发布分开收口。本次将以下开关的仓库默认值改为开启，而不只写入被 Git 忽略的本机环境文件。

| 能力 | 默认值 | 回退方式 |
|---|---|---|
| Replay 快进、周期摘要和安全逐笔区间推进 | `REPLAY_FAST_FORWARD_OPTIMIZATION_ENABLED=1` | 后端设为 `0` 并重启 |
| 窗口内行情请求、指标流共享和工作调度 | `VITE_CHART_WINDOW_BROKER_ENABLED=1` | 前端设为 `0` 并重启开发服务器或重新构建 |
| 批量 K 线传输 | `VITE_KLINE_BATCH_STREAM_ENABLED=1`、`KLINE_BATCH_STREAM_ENABLED=1` | 网页部署前后端都设为 `0`；桌面包重新构建时自动传递前端解析值 |

前端未设置变量时开启，显式 `0`、空字符串和非法值仍关闭；保留现有严格解析约定（字符串 `true` 不等于 `1`）。桌面构建的 `desktop-runtime-config.json` 同步采用此默认值，防止前端默认开启、打包后端却被注入 `0`。

16 图、原生多窗口、64 图三个容量开关的仓库默认值不变；本机原有显式覆盖不变。以上共享能力不要求启用容量开关，也不代表完成四物理显示器、混合 DPI 或热插拔验收。

## Replay 启用前补齐的边界

专项回归发现旧代码在请求跳过逐笔数据末尾时，会让全局协调器越过来源终点，随后被 `FINALIZE_DEFERRED_TERMINAL` 拒绝。使用修改前的配置重新运行，也能复现。

现在只在请求越过绑定尾部时，读取各不可变来源的有界目标描述，并将目标限制在来源终点。不能直接使用绑定的 `actual_replay_end_ms`：它可能是最后一个桶的开盘时间，直接截断会遗漏该桶内成交。来源终点同时保留盲模式时间映射。新增单标的和双标的持仓末尾测试，验证终态、精确终点及账户审计。

旧测试分别验证新的区间协调器和保留的单适配器路径。兼容路径的逐块取消、检查点摘要跳跃仍被单独覆盖；区间路径验证实际游标、组件、来源链及账户结果，不把不同提交修订号产生的全状态哈希差异误当作资金差异。

## 仍关闭的候选

- `BACKTEST_SPECIALIZED_BAR_ENABLED`：未测出稳定收益。
- `BACKTEST_REUSE_HISTORY_JSON_ENABLED`：长区间配对基准出现退化。
- `BACKTEST_REUSE_DUAL_CHART_BARS_ENABLED`：长区间收益不稳定且增加在途内存。

交易解释、OKX 归档、自动下载和自动 GC 不属于本次性能默认启用范围。

关闭优化仅切换后续执行路径；已经产生的 Replay 区间历史继续由当前读取代码处理，不承诺旧二进制能够读取新格式。
