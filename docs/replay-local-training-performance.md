# 本地训练回放：减少重复派生计算

后续实现和 schema 20 迁移见 [安全区间的精简历史与按需派生](replay-compact-interval-history.md)。下文保留第一轮无 schema 变更的历史测量。

## 产品目标

回放用于本地交易训练和复盘，没有排行榜，也不要求阻止用户修改自己的本地记录。撮合、事件暂停、资金计算、恢复和复盘必须正确；防止本地用户作弊不是同步计算的理由。训练界面仍应按进度展示行情。

该约束已写入 `backend/app/replay/AGENTS.md`。后续存储格式调整不以旧版本所有哈希和派生账本字节完全相同作为产品要求，但必须明确兼容方式，并验证交易结果和复盘重建。

## 已调整的计算

1. 安全记录区间的风险指纹只在事务入口和出口计算。区间只允许单轨公共 MARK_INDEX 输入，进入时检查已完成的风险状态，逐帧拒绝经纪商交互；内部按标记价是否变化决定是否重新估值。事务结束后才发布新指纹，失败时清除事务上下文。普通推进仍走原来的完整状态检查。
2. 同一区间内权益样本按 `(run_id, resolution, bucket_id)` 合并，同一个桶只写最终值。EVENT 和每个独立分钟桶仍保留。提交前批量写入，再执行保留窗口清理；创建时间保留第一次插入的语义。公共时间 JSON 和 revision 每帧只处理一次。
3. 已存储交易规则按完整 JSON 内容缓存解析结果，最多 128 个。规则及保证金档位对象不可变；内容变化会重新解析和校验，错误内容不进入缓存。缓存用于估值、风险、资金费和组件同步中的六处重复解析。

没有数据库迁移，没有更改撮合或资金费公式。本次仍生成逐基础事件状态哈希、估值账本和全局检查点，尚未实现以区间日志代替这些历史记录，也没有把日/周推进变成真正的区间跳跃。

## 测量与证据

测量脚本：`output/replay-latency-sampling-20260909/benchmark_local_cleanup.py`。before 在独立测量进程中加载提交 `2c4674b2` 的原 storage 方法；after 使用工作区实现。均使用合成行情和独立数据库，不读取或修改用户回放会话。

一次推进到日线边界，计时部分包含 1439 根基础 K：

| 执行次序 | 实现 | 耗时 |
| --- | --- | ---: |
| 1 | before v1 | 13.52 s |
| 2 | after v1 | 19.48 s |
| 3 | after v2 | 12.86 s |
| 4 | before v2 | 16.14 s |

v1 包含完整逐根参考对照，v2 只运行记录区间路径。after v2 另包含公共时间编码提到分辨率循环外的小调整。全部运行的最终状态、曲线、账本、全局顺序和关键复盘证据一致。工作机运行波动明显，这些样本不足以宣称稳定的延迟改善，更不能当作浏览器延迟。

回归新增工作量上界检查、重复标记价对照、权益批量写入失败回滚、规则缓存不可变性和修改失效检查。扩展回归及工作量计数保存在同目录的 `cleanup-regression.log` 和 `cleanup-regression.xml`。

最终扩展回归：515 passed、3799 deselected，4 条既有 FastAPI 弃用警告，耗时 449.71 秒。Ruff 和 `git diff --check` 通过。工作量用例中，234 个区间内基础事件组成 8 个区间，仅计算 16 次风险指纹；权益行写入从原来的 936 次降至 501 次。该用例同时对照普通逐事件路径的最终状态、保留曲线、账本、关键复盘和重启结果。

## 尚需替换的主要开销

逐根完整状态哈希、纯估值账本和全局检查点依然是后续重构对象。下一阶段需要版本化的区间记录、必要边界快照，以及曲线和中间复盘位置的按需重建；不能仅删除现有记录而让复盘缺失。最大回撤等路径指标需要精确摘要或回退。此次调整减少重复工作，不代表这项存储重构已经完成。
