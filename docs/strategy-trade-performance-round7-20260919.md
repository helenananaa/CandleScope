# 第七轮：检查点历史 JSON 编码复用

继续基于 `172ae4dd` 和前六轮未提交修改工作。未提交、合并、部署或修改运行服务数据库。

## 当前版本分段诊断

对 100,000 条合成聚合成交，在实际 spawned worker 内增加检查点阶段计时。优化前 102 次检查点的累计时间约 2.533 秒，其中 provider 快照与编码 0.150 秒、历史编码与预算 1.356 秒、最终 JSON 组合 0.354 秒、检查点哈希 0.017 秒、数据库发布 0.588 秒。历史编码包含在内核快照和总检查点计时中，不能把所有计时字段相加。

上述数据附带 cProfile 和计时器开销，仅用于定位，不等于实际延迟。证据：`performance-evidence-20260919/round7-profile-before.json`。

## 实现

原先历史尾部先编码计算完整字节预算，再作为清单的一部分重编码，最终检查点拼装又编码一次。现在：

1. 尾部只编码一次；以规范 JSON 顺序组合 `chunks` 和 `tail` 清单。
2. 用同一段清单 JSON 计算精确字节数，并临时关联到当前快照的清单对象。
3. 最终检查点仅在已知历史字段、对象身份一致时复用片段，其他字段照常规范编码。
4. 片段在拼装完成或失败时清空；下一次 `begin()` 也清空，避免跨检查点滞留。片段来自同步生成的内部快照，不接受外部 JSON 片段输入。

候选功能默认关闭：`BACKTEST_REUSE_HISTORY_JSON_ENABLED=0`。只有显式设为 `1` 才启用，原因是短/长区间收益尚不稳定。BAR、普通逐成交和双时钟的已有分块格式均支持。数据库格式、分块哈希、最终检查点 JSON、逻辑完整字节预算不变；未降低数据校验或检查点频率。此次未修改数据库发布算法，也未实现行情解析复用。

## 验证

- 5 种模式/格式组合，分别覆盖 0、1、255、256、257、513 条记录，核对新旧最终 JSON、分块内容和逻辑完整字节数。
- 覆盖中文、换行、引号、反斜杠、emoji、小数尾零及空数组。
- 被替换的清单对象不能复用旧片段；第二次拼装或下一次检查点不会读到旧缓存。
- 普通成交/双时钟实际服务从同一个排队数据库复制运行，比较每次落库的 sequence、payload_json、state_hash、history_chunks，以及完整 result/report。
- 扩展回归覆盖持久化恢复、分块损坏拒绝、离线回滚、账户/撮合与成本敏感性结果。

## 性能复现

固定前序优化开启，只交替本轮开关；保留完整成本分析和周期检查点。每根 K 线 10 条行情，SMA 3/5，每 1,000 条行情保存检查点。每组 3 对，第二对先开启优化。基准与测试串行执行。

```powershell
$env:PYTHONPATH='backend;packages/candlescope-plugin-sdk/src;packages/candlescope-backtest-sdk/src'
python -m scripts.benchmark_trade_strategy --round7 --events 100000 --pairs 3 --output docs/performance-evidence-20260919/round7-dual-100k.json
python -m scripts.benchmark_trade_strategy --round7 --events 300000 --pairs 3 --output docs/performance-evidence-20260919/round7-dual-300k.json
```

计时含 worker 启动、策略、逐笔撮合、完整成本分析、检查点和报告持久化，不含数据导入、HTTP 或浏览器。结论限于本地合成数据，不能直接外推至真实交易所全量数据或生产性能。

| 300k | 2 | 22.547 s | 27.967 s | -24.04% |
| 300k | 3 | 22.019 s | 21.627 s | 1.78% |

九对完整 result/report 全部一致。100k 三对均有改善，但 10k 三对略慢，300k 两对较慢、一对略快，尚无跨负载稳定收益，因此保持默认关闭。不能用 300k 中位数的微小改善掩盖两对退化，也不能只选 100k 数据宣称普遍提速。

补充诊断 `round7-profile-after.json` 的总检查点时间为 3.441 秒，历史编码 1.692 秒、JSON 组合 0.466 秒、数据库发布 0.887 秒。其他未修改阶段也出现较大耗时变化；分段样本不能证明编码阶段净收益，更不能确定退化原因。需要更受控的重复测量与分配开销分析后再考虑默认启用。
