# 多商品 BAR 区间推进

状态：核心路径已实现，阶段验收未通过；整体计划尚未闭环。
`REPLAY_MULTI_BAR_INTERVAL_ENABLED=0` 保持默认关闭。

目标是在准备完成、八商品同时持仓的常规 BAR 工作负载中，点击到主图更新
P95 达到日线 200ms、周线 500ms。服务端微测不替代浏览器验收，复杂事件的
精确回退、首次索引准备和历史读取分别报告。

## 执行与恢复

新内部命令 `_training_multi_shared_indexed_interval_v1` 只由共同账户协调器
发出。仅支持共享不可变市场索引、2–8 个 FULL BAR/HEDGE 商品、盘口 OFF、
非历史精确账户及 OFF/HISTORICAL_EXACT 资金费。多头、空头、双向仓和
全仓/逐仓使用逐腿保守权益下界、保证金上界；无法证明安全意味着继续细查，
不代表可以直接强平。挂单、资金费、规则和模拟事件保持原事件屏障。

各 Actor 在提交钩子处等待同一屏障。所有候选、游标、恢复检查点、公共输入
区间引用和账户结算写入一个 SQLite 事务，提交后才发布事件及确认命令。
提交失败走 Actor 原回滚路径。取消在准备完成时检查；进入共同提交后先完成
提交/回滚再释放任务，避免数据库已提交而内存退回旧状态。
浏览器只取得选中商品的控制权时，协调器先按原有规则取得其他商品的控制权，
再重新读取八商品版本。已有其他客户端控制的商品仍拒绝接管；不会绕过租约校验。

父命令意图与第一个区间一起写入，每次共同提交记录全部商品的恢复游标、状态
及账户指纹。确认前崩溃的重试回到共同账户协调器，不能进入旧的单 Actor 扫描器。
已被其他操作改变的账户拒绝自动续跑。测试覆盖第一个区间后和外层确认前两处
子进程强制退出，以及候选编码失败时所有 Actor 的内存游标回滚。

新命令的检查点明确保留 16 根基础 K 线传输尾部及共享源锚点，恢复时仍严格
校验声明的容量和计数。完整已揭示市场历史通过原历史接口读取，不随传输尾部
裁剪丢失。容量记录在内部命令的 `transport_tail_bars` 中；没有该字段的较早
多商品 v1 命令仍按 64 根解释。普通旧命令和旧检查点保持原解释。
短区间也先裁剪较长的预热尾部并更新前缀计数/链，避免容量声明与恢复状态不符。
这些小检查点优先使用已有的完整压缩封装，避免为短尾反复构造结构差分。
差分基础缓存容纳 8 个基础，每个最多 4 MiB 原始 JSON；未知原始大小的外部
压缩基础仍不缓存。

训练 schema 23 增加 `replay_multi_bar_interval`，记录已提交区间及组合汇总。
旧 schema 19–22 增量升级。即使新开关关闭，启动新代码也会升级数据库 schema。
旧代码不能读取新的 schema/内部命令；回滚代码须恢复升级前数据库备份，
关闭开关不是格式降级。新开关在财务、恢复和性能门槛全部通过前不启用。

## 组合统计与历史

组合权益按参考全局时间的同时间事件组计算，不能把各商品独立极值相加。
正常精度使用经 60 位 Decimal 等价范围检查的缩放整数；其他精度保留 Decimal
公式。区间汇总可组合，包括跨区间回撤。新的最低权益边界产生真实恢复锚点，
而不是拿最终检查点冒充较早状态。

组合历史保存账户基础及已消费公共输入引用；按需重建时检查归档校验和、所有权
和已揭示时间边界。旧权益接口的选中商品语义单独保留，不用组合数据偷偷替换。
开启新路径时，HEDGE 索引缓存总上限为 800,000 个事件、至多 4 个快照，支持
八个市场的准备窗口；关闭时仍为 200,000。缓存不保存未来逐分钟账户状态。

市场对象另外保留至多 128 个不可变区间汇总，复用同一命令内估值和交易投影的
重复区间读取。CPU 汇总和候选 BAR 构造在工作线程执行。

后续优化使用可复用的市场整数价格块和二分时间目录；每次请求只扫描目标区间，
不再重建、排序整组公共价格事件。账户价格汇总只计算收盘极值与有序涨跌对，
展示用的完整 OHLCV 汇总仍保留独立路径。小型不可变节点树批量准备，已校验的
共享行也供精确末端 `peek` 使用，避免为一条边界事件重读整页原始归档。

共享视图重建可复用原市场范围，但必须以当前链种子、游标和 builder 基础重新
绑定；测试与冷重建的链及完整 builder 状态一致。共同候选使用一个工作线程批次，
幂等记录共用一次数据库读取；已经激活的区间引用不再启动空写事务。新低点仍
保留真实恢复锚点及单独提交，但安全前缀直接复用已验证计划。

冻结数据快照保留最多 128 MiB、16 项已验证字节缓存；文件签名变化重新校验，
删除或损坏仍报错。该缓存只保存不可变市场快照，不保存未来账户状态。

## 展示协议

推进 API 路由和请求不变。请求展示尾部时，多商品响应可附带同版本的
`data.market_tracks`；不改变持久化命令结果。前端在多商品 DISPLAY_BAR 请求
期间合并普通价格导致的主图与账户展示，权威状态照常更新。断线、重绕、控制权
变化、订单和成交变化继续走原即时处理路径。可选投影失败仍使用原恢复路径。
BAR 展示推进也支持进度查询和取消；短操作不闪现进度控件，超过 250ms 后显示。
推送复用同次提交的有界投影，并合并被更新的待发消息。前端以持久化 Actor 修订号
拒绝延迟的旧账户投影；不能把服务重启后归零的播放 generation/tick 当成永久版本。

## 第三轮实现：准备、提交和组合历史

准备入口可接收当前控制客户端标识，在打开工作台前统一取得八商品空闲控制权；
已有其他控制者时不接管。主商品心跳只续租本组已加载且属于同一客户端的成员。
安全区间的最终确认与八商品候选共用事务，普通推进由两次事务降为一次；
新回撤低点仍保留真实恢复锚点，因此可能需要两次事务。未订阅商品使用已有
RESYNC_REQUIRED 事件，省去不可见图表尾部编码；重新订阅仍取得完整当前快照。

不可变标记价采用带校验的压缩价格块，准备时构建，损坏或缺失时从已校验原始输入
重建。价格事件复用冻结数据，当前已揭示图表尾部也在准备阶段缓存；这些缓存不含
未来账户状态。组合曲线在用户展开后按需读取，估值和 NDJSON 导出在工作线程执行。
导出含记录区间的精确价格输入、仓位基础、币种及校验尾，能够独立重算该覆盖范围；
它不是整个训练数据库的可迁移备份。API 和界面明确标记旧历史覆盖不完整。

仅在多商品开关开启时，SQLite 的 PASSIVE WAL 检查点移至短暂空闲期，连续写入
达到批次或增长门槛时也执行维护。仍使用原写连接和互斥锁，保持 synchronous=FULL，
每个提交继续同步 WAL；检查点失败恢复原自动策略。长期读事务仍可能阻止 WAL
回收，并通过指标报告剩余页数。此设计依据
[SQLite WAL 性能说明](https://sqlite.org/wal.html)，不靠降低持久性达成速度目标。

当前轮次证据保存在 `output/replay-performance-followup-20260912/`。
新路径继续默认关闭，历史结果与本轮结果必须按各自构建和测量口径分别使用。

第三轮日线 100 次中，连续操作主图数据更新 P95 为 287.6ms，最大 509.9ms，
仍未达标；后续帧回调 P95 为 339.4ms。周线保留 9 次诊断，发现一轮异常帧延迟，
未完成本轮 100 次周线验收。内部七日组合曲线重建约 550ms，最新 HTTP 读取约
1.39 秒、约 9.8MB 的精确区间导出约 1.05 秒；不可混用内部与端到端口径。
96 项主实现回归、30 项最后存储/取消/崩溃回归、403 项前端测试以及真实存档
恢复通过。详细失败边界和原始证据见
[第三轮候选报告](../output/replay-performance-followup-20260912/report.md)。

## 两阶段低点提交

新低点与终点现在可先分别构造八商品候选，在一个事务中按阶段写入，保留两组
真实命令记录、检查点、区间曲线和全局事件顺序。Actor 在最后一个提交屏障之前
不更新幂等历史、不发布事件、不发布检查点环；第二阶段构造或写入失败会恢复
所有 Actor 的初始状态。批次入口命令的响应仍与自己的持久化幂等记录一致，
训练协调器负责最终终点响应。没有足够 BAR 支撑低点两侧时沿用精确回退。

区间摘要、曲线基础编码及价格范围查询提前在候选工作线程完成，写事务保留
版本验证和实际账务/恢复记录写入。账户侧栏的数字格式化器按语言和小数位数
有界复用，不改变数字舍入规则。相关证据在 `output/replay-performance-phase-20260912/`；
开关仍默认关闭，性能结论须使用该目录最终候选的实测口径。

本轮最新 100 次日线中，连续操作主图数据更新 P95 为 232ms、全部操作 P95 为
257ms，仍未达到 200ms；首次最大 648.4ms。周线仅完成 9 次诊断，主图更新
最大 423.2ms，不能当作完成 100 次验收。真实存档重开后八商品游标均为 30,240，
账务与区间记录一致。独立剖析显示低点事务仍有约 982 次 SQLite execute，后续
重点为阶段级批量读取和复盘/账户投影，而非继续只减少事务。详细口径与验证范围见
[两阶段提交报告](../output/replay-performance-phase-20260912/report.md)。
