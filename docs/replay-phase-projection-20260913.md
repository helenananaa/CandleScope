# 大周期回放：阶段级账户与复盘投影

本轮继续优化八持仓 BAR/HEDGE 大周期推进。商品推进、低点和终点检查点仍在同一
SQLite 事务内提交；`synchronous=FULL`、精确回退和新路径默认关闭保持原有契约。

## 实现

- 每个阶段批量读取商品摘要所需的元数据与历史账户状态，避免八商品分别重复查询。
  上下文只属于这次事务的这个阶段；第二阶段重新读取，失败后不会缓存到后续命令。
- 各商品摘要不再对尚未对齐的八商品账户反复刷新权益。阶段末应用全部 pinned mark，
  原风险投影统一计算权益，并保留原来最后一个商品的 summary revision。
- 区间价格极值直接传给交易结果投影，消除摘要同步和随后区间同步的重复调用。
  价格极值、成交、交易复盘均保留。
- pinned mark 与规则查询批量读取。当前生效规则仍按生效时间和修订排序；风险核查
  所使用的最新规则仍按修订排序，未将这两个不同的规则选择口径合并。
- 同一复盘事件的多商品锚点共享商品元数据与容量累计值，关联行使用批量插入。
  每个真实锚点继续独立校验与持久化，完整投影哈希及公开时间编码在同次追加内复用。

## 正确性

- 新增全仓、逐仓八商品对照：低点和终点的权益、修订、仓位、账户、交易极值、
  复盘分类、复盘 domain 及锚点 payload hash 与旧逐商品摘要流程一致。
- 新增规则选择对照覆盖生效边界、未来修订、空时间、非 FULL 商品和其他 run。
- 扩展回归有 137 个不同测试通过，覆盖原逐事件财务对照、双向仓位、风险、输入、
  复盘锚点预算、取消、回滚和恢复。
- 另有 1 个基线既存失败：`test_deferred_broker_frame_does_not_observe_later_bars`
  尝试修改只读内部快照，被 `immutable_json.py` 拒绝。使用本轮修改前的模块快照
  复现了同一失败；未将其算作通过，也未修改该测试或快照契约。
- 真实存档的优化前后 20 次推进结果均通过账户审计，八商品仓位、账户及游标一致。
- 最终浏览器存档重开通过：8 个商品均恢复到源游标 30,240，恢复约 11.72 秒、完整
  账户审计约 22.29 秒，120 根历史可读；账户、仓位、订单、成交、账本、保证金桶和
  区间记录表的完整摘要在重开前后相同。该耗时属于恢复，不计入点击延迟。

调用从此前 982 次降到 **682 次**，约减少 31%；交易结果投影从 32 次降到 16 次。

调用次数，`executemany` 批量插入仍会执行每一行必要写入，并非宣称删掉了所有这些
SQL 工作。剩余成本仍集中在复盘投影、规范化编码与风险/全局检查点。

回执随后到达，因此指标完成必须从本次主图更新开始识别，不能限定在 HTTP 回执后。

保留在正式总样本中，并记录旧采样器的超时标记。未准备完整历史的另一条 1.5s
操作单独保留为校准失败，不冒充 prepared 运行。rAF 仅表示呈现机会，不是屏幕像素时间。
