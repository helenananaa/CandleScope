# 交易所公共行情多代理线路

入口：**设置 → 网络连接 → 多线路**。最多配置 16 条显式 HTTP(S) 代理线路；原有系统代理、自定义代理和直连模式继续可用。多线路模式没有可用线路时会返回错误，不会自动回退到直连或系统代理。

## 配置与使用

每条线路包含名称、代理地址、出口组、REST 并发请求上限、实时订阅容量、交易所允许列表和启用状态。地址需包含端口，例如 `http://127.0.0.1:7890`；支持 URL 中的代理认证信息。出口组只能使用字母、数字、下划线或连字符；交易所列表填写内部 ID，例如 `binance,okx`，留空表示全部。第一条启用且适用于目标交易所的线路为初始主线路，可以通过“设为主线路”调整顺序。

- **主备切换**：REST 优先选择最靠前且额度、健康状态和并发允许的线路；所有线路都需等待时选择等待最短的线路。
- **智能均衡**：REST 综合额度等待、并发占用、平均请求耗时和连续失败选择线路；新增和重新接入的 WebSocket 订阅综合容量占用、近期接收流量、投递积压和断线情况选路。仍在运行的相同描述符优先复用已有线路。
- **实时 WebSocket**：保持已有连接，连续失败 3 次后隔离线路并尝试备用线路。已切换到备用线路的健康连接不会因为主线路恢复就立即切回。切换前释放旧会话和队列，避免混入旧订单簿数据。原生复用连接按整个订阅批次选择线路，一个实际连接保持在一条代理上；健康批次不会为了均衡主动拆散。

实时订阅容量默认 **64**，可设置为 1–4096。旧配置自动使用默认值。相同描述符的多个会话共享一份容量，停止最后一个会话时才释放该描述符的容量。容量达到上限或所有线路冷却时，会等待可用容量，且不把这种等待当作网络失败。原生共享连接的批次大小受最小适用线路容量约束，保证备用线路能够承接批次。容量是本地调度上限，不是交易所的官方连接数上限，也不代表多了一份出口 IP 额度。

**出口组表示实际出口 IP 的额度归属，不等同于代理地址。** 两个不同端口或不同代理地址仍可能使用同一个出口。它们应使用相同组，例如 `shared`。只有确认实际出口独立，才使用不同组，例如 `exit_a` 和 `exit_b`。不知道出口关系时保持默认 `shared`。这版不会自动探测公网出口 IP，也不会将多条本地代理自动视为多份额度。

示例（PUT `/api/v1/settings/proxy` 的配置体）：

```json
{
  "mode": "pool",
  "strategy": "balanced",
  "custom_proxy": null,
  "routes": [
    {
      "id": "primary",
      "name": "主线路",
      "url": "http://127.0.0.1:7890",
      "egress_group": "shared",
      "enabled": true,
      "exchanges": [],
      "max_concurrency": 4,
      "max_ws_subscriptions": 64
    },
    {
      "id": "backup",
      "name": "备用线路",
      "url": "http://127.0.0.1:7891",
      "egress_group": "shared",
      "enabled": true,
      "exchanges": [],
      "max_concurrency": 4,
      "max_ws_subscriptions": 64
    }
  ]
}
```

“保存代理”沿用现有运行时重启传输流程。“测试连接”测试当前编辑的草稿，对适用线路依次访问 Binance Spot、Binance Futures 和 OKX 的公共探测接口，不保存草稿。这是可达性检测，不是实际出口独立性检测。每次网络请求最多等待 10 秒，多条线路的串行检测可能较慢。

## 额度、失败与诊断

公共行情 REST 在选择线路后，按出口组预留相应额度。额度预留携带不可变的线路上下文，实际请求不会重新随机选择代理。请求完成、失败或取消后会释放线路并发占用。CCXT 历史客户端复用同一条线路绑定的配置；停止传输时关闭各线路客户端。

429、418 和交易所等价限流响应进入现有额度管理器；相同出口组共享等待状态。418 的 IP 熔断在同交易所、同出口组的不同端点间共享。它们不计作普通代理网络故障，也不会在收到同一次限流响应后立即换代理重放。之后的新请求可以选择另一个有可用额度的独立出口组。按 API key、账号或用户定义的额度不会因为代理数增加而复制。

网络错误及服务端 5xx 会增加线路失败计数并触发有上限的冷却。状态接口 GET `/api/v1/settings/proxy/status` 返回进行中请求、REST/WS 观测、请求耗时和额度等待；代理认证信息会脱敏。界面的状态对应已保存配置，没有真实耗时样本时不会显示估算延迟。配置文件保留连接所需凭据，诊断脱敏不表示凭据加密存储。

第二版新增三个独立计数：`ws_subscriptions` 是去重描述符数，`ws_sessions` 是含启动中会话的容量租约数，实际连接数是 `native_websockets + ccxt_physical_websockets`。多个会话可以复用一个 CCXT runtime 和实际连接，不能用会话数代替实际连接数。CCXT runtime 按线路 ID、出口组及既有连接配置隔离；同线路上的既有 OKX 描述符分片规则继续生效。

编辑地址、出口组、容量等路由参数后，界面会隐藏该线路的旧配置运行计数；保存成功后立即重新获取状态，避免把旧线路的计数显示到新配置上。

## 第三版：实测流量辅助选路

每条线路的 `ws_traffic` 提供最近 30 秒的消息数/秒、载荷字节数/秒、断线次数，以及累计消息/载荷/断线数和距上次接收的时间。窗口使用单调时钟和每秒聚合，最多保留 30 个桶；开始接收不足 30 秒时也以 30 秒作分母，避免单次突发过度影响分配。配置反复更换时最多保留 128 个代理地址的观测，不持久化消息内容。没有消息样本时，上次接收时间为 `null`。

原生 WebSocket 在传输接收入口计数，覆盖订阅确认、无效载荷和握手预取消息；预取消息后续投递不会再计一次。CCXT 在实际客户端接收入口、JSON 解码和订阅分发前计数，避免把多个 watch 会话复用的消息、缓存结果或投影事件重复统计。文本按 UTF-8 字节计数，二进制按接收到的载荷长度计数；不含 WebSocket 帧、TLS、TCP 等网络开销，也不是网卡带宽测量。交易所自定义二进制压缩按解压前载荷计数。主动停止不增加断线计数；原生连接超时重建和 CCXT 已连接客户端的错误/远端关闭会计数。

`queue_size` 和 `queue_capacity` 是 CCXT 会话投递队列的合计；`queue_pressure` 是各会话队列占用比例的最大值。没有可观测队列时容量为 0，界面隐藏队列行，不能据此断言原生连接或 CCXT 内部缓存没有积压。关闭会话即移除其队列观测。

智能均衡先排除容量耗尽、冷却和出口熔断线路，再优先复用仍在运行的描述符。其余线路按“订阅容量占用比例 + 相对流量压力 × 0.5 + 最大队列占用比例 + 近期断线惩罚”评分；相对流量取消息率和载荷字节率相对可选线路最大值的较大值，断线惩罚每次 0.1、最高 0.5。容量预留立即生效，防止同时启动的订阅都涌向一条空闲线路。没有流量样本时沿用容量均衡；记忆的原线路只参与评分相同时的偏好，不覆盖实测负载。这个评分是分配启发式，不表示线路超载或达到真实带宽上限。

已有健康连接不会被主动迁移。原生重新建连、CCXT 会话释放旧 runtime 后重新接入时会重新评分；CCXT 在同一个共享 runtime 内进行 WebSocket 缓存清理和重连时仍保持线路，避免影响其他会话。主备策略继续保留其线路优先级，流量只用于诊断。

## 本阶段边界

- 覆盖公共行情历史请求、原生目录 HTTP 请求和原生/CCXT 实时连接的主备切换；不覆盖私有下单、余额或账户会话。
- 第三版使用实测接收流量和 CCXT 投递积压辅助新建/重新接入的订阅选路，不按 CPU 消耗调度，也不强制搬迁健康会话；切换策略或容量配置通过既有保存流程重启传输后生效。
- 归档下载、部分启动目录和独立的通用 CCXT 目录初始化仍使用首条适用线路；CCXT 隐式元数据调用保留其自身限速，不声称每个隐式请求都由宿主额度管理器逐一记账。
- 本阶段未新增覆盖所有交易所的出口 IP 建连速率限制器；保留既有适配器和 CCXT 控制逻辑，实时订阅容量不代替交易所特有的连接或控制消息限制。
- 额度和健康状态在一个 Python 事件循环内共享，没有提供跨进程协调，也没有新增按用户公平调度。
- 新界面文案提供中文、繁体中文、英文、巴西葡萄牙语和韩语；其他现有语言暂使用新增英文文案。

2026-10-07 的第一版验证使用回环 HTTP 代理、假交易所和可控 CCXT 会话，覆盖线路选择、共享出口预算、独立出口熔断、限流不立即重放、请求取消和实时故障切换。第二版增加真实回环 HTTP CONNECT 代理与 WebSocket 服务器，验证两条线路分别承载 WebSocket、容量耗尽时不产生额外连接、关闭后计数归零；另用受控 CCXT runtime 验证多线路隔离与相同描述符复用。浏览器检查使用真实组件的隔离页面，未调用真实交易所、未保存实际配置。由于当前电脑运行 TUN，未完成真实公网出口、交易所连接及吞吐容量验证；实际接入多条代理后仍需单独确认出口组划分和实时稳定性。
