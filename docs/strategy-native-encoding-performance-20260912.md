## 实现

1. **已证明兼容的原生 JSON 编码。** 使用项目已固定的 `orjson==3.11.3`，只对已验证的字符串/整数/布尔/null 树启用。字节级比对发现 U+007F 与 Python ensure_ascii 编码不同，因此该字符、非 ASCII、浮点及复杂对象走原路径；大整数超出 native 范围也回退。没有原生模块时仍使用标准实现。
2. **固定结构的空决策编码。** 对普通空订单列表、整数序号/时间和字符串前置哈希，直接构造与原 sorted JSON 完全相同的编码，减少临时字典。普通决策与带 provider decision 的 HostPlan 保持原逻辑。前置字符串仍由标准编码器处理 Unicode/转义。
3. **目标仓位状态哈希复用。** 仅缓存精确匹配的 quantity/targetExposure 两字段短字符串负载，额外字段和其它类型保持完整计算；返回的可变 payload 仍独立。
4. **运行内固定信息复用。** 自有 provider 的方法绑定、能力描述和 BAR 输入元数据在 prepare/restore 后复用，逐根执行的截止时间仍由父进程监督。无订单时不再创建空的撮合/入队列表。
5. **对象输入边界检查。** 保留固定 schema 和原生类型检查，由 native 编码器证明 53 位整数及整体 ASCII/字节上界。上界同时受 SDK 当前字符串和消息限额约束；不兼容或缺少模块时回退，不放宽 SDK 限制。
6. **有界数值规范化缓存。** SDK 只缓存短、非科学计数法的常用值；大数和长数值继续完整计算。不同 Decimal 精度、错误类型和大指数输出均有对照。相同 OHLC 原始拼写可复用已验证的 open 格式化结果，保留尾随零语义。

延续上一轮的直接对象通道、敏感性矩阵专用证据、报告复制与校验去重。没有以舍弃报告、减少风险检查、改变成交顺序或隐藏分析时间来达标。
