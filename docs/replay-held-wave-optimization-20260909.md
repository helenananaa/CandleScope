# 持仓推进：内部边界提交合并与复盘快照过滤

本轮在既有待提交修改上继续优化，保留逐基础事件执行和 SQLite FULL 持久化。适用场景是 BAR、HEDGE、非历史精确账户、无历史盘口要求且当前完整事件波次没有后续模拟输入；其他场景继续走原路径。

## 行为

同一基础 K 线边界的 HEDGE 标记覆盖、风险检测和全局事件/检查点现在可以在一次 SQLite 事务中完成。只有风险检测后没有待处理清算才会同时提交全局记录。存在清算时，只提交风险状态，返回原有清算协调流程，完成后再记录全局事件。基础 K 线仍逐根执行，未跨资金费、模拟事件、精确账户或不完整同时间事件组跳跃。

事务成功后才更新内存风险指纹；全局检查点写入异常会一起回滚风险和全局写入。通知仍发生在提交之后，没有提前确认未落盘的数据。

复盘 SOURCE_EVENT 初筛只有权益回落、且尚未低于已有最低权益时，直接跳过。原逻辑会先构建完整账户和账本投影，再过滤掉该候选；新逻辑提前执行同一判定。真正的新低、成交、订单、仓位、资金费与清算候选仍走完整投影与原有哈希链。

两条路径使用同一持仓存档副本和相同五个 DISPLAY_BAR 命令。下列是带调用计数探针的独立 ReplayService 本地结果，不是浏览器端到端帧时间，也不是长期 P95 结论。

| 五次请求耗时 ms | 1255 / 1062 / 1144 / 1034 / 1028 | 765 / 603 / 626 / 619 / 658 |
| 中位数 ms | 1062 | 626 |

五次最终 cursor/state_hash 全部一致；数据库中的 12,640 条全局事件序号与排序哈希、499 条复盘事件序号与事件哈希逐行一致。中位数下降约 41%，但不是所有数据区间都会有 15 个可过滤的权益候选；创新低等真实关键事件仍需构建投影。

此前 `_component_state` 的 93 次计数是访问次数，实际缓存重建只有 15 次。本轮没有把缓存访问数包装成减少了 93 次完整构建。

## 验证

新增测试覆盖合并与逐事务参考路径的返回值、市场轨道、全局事件、复盘投影一致；四根基础 K 线少四次提交；重启后的同命令幂等结果；检查点故障时风险与全局写入回滚且不污染缓存；真实待清算状态保留原有全局提交边界；非新低回落跳过完整投影而新低仍进入完整路径。

验证结果：新增 4 项回归通过；完整回放选择集为 1074 passed、1 failed（3180 deselected）。失败是 4 轨 AGG_TRADE 测试获取控制权阶段的 revision 冲突，尚未进入本次 BAR 合并路径，其测试夹具租约为 1 秒。随后 2/4/8 轨矩阵复跑 3 项通过，包含整个多轨模块、复盘模块和新增测试的最终定向回归 48 项通过；没有延长租约或修改测试门槛。该偶发失败保留记录，不写成整组全绿。Ruff 与 git diff --check 通过。

本地证据在 `output/replay-latency-sampling-20260909/wave-*.log`，以及 `output/replay-latency-20260909/service-profile-wave-{reference,final}.json`。实际回放库已在重启前备份；本轮未提交或推送。

当前仍保留 15 次逐根执行和 32 次写事务，不能声称持仓已达到空仓速度。进一步跨事件合并 actor 提交需要更大范围的恢复设计，不包含在本次变更中。
