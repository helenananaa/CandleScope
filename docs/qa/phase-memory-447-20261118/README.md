# #447 分阶段内存、公平许可与10007m进展

按用户授权实现阶段/页级工作额度、图表公平分配，并允许有依据地增加预算。产品 `b821d03773a07fd3c378a369db6bb1a3d41bf2c9` 叠加 #474；本项不替代 #463 的净≤3秒和完整生命周期验收。

## 实现

- 新增稳定图表 owner 的资源上下文，由原 scheduler 的公平 owner 传递到同一 MemoryBudget。相同优先级的等待者按 owner 服务轮次轮转，活跃扩容优先以保证工作可完成；两秒老化防止低优先级需求一直被新任务挤掉。等待记录和轮转记录有界，未加上层整轮执行槽。
- 规划只声明约20.06MiB规划峰值，不再宣称每个 planner 将占整个工作 owner 上限。规划结束，先将 scratch 完整归还，再等待下一阶段额度，原协程/计划继续。跨阶段保留的计划对象由原 MemoryBudget 的 `history-backfill-plans` 临时 owner 记账：先给64KiB、声明4MiB上限，规划后按实际可达对象计量；它不存储行情，不是新缓存、下载器或 writer。
- 合格闭合原生 REST 页复用既有流式提交：物理页在请求前取得原子额度，原始页和规范化空间到现有 canonical writer 完成采用后释放。共享获取仍保留到最后一个消费者释放；真正延期通过原 source journal 恢复已收到数据，原始删除许可不更新。
- 有来源 composition policy 的归约复用现有256行 canonical 流和有界目标输出，不按全部来源行保留归约缓冲。档案/扩展等不满足页合同的路径，先异步取得完整批次额度，再走原完整结果合同；不偷偷绕过归档、身份、增强字段或修订围栏。
- 内存预算按用户授权调整：共享总额256→**512MiB**，补齐工作64→**192MiB**，另有**32MiB**计划对象记账上限。已有显式配置优先；预算覆盖受管对象/工作额度，进程RSS和physical footprint另记，不能把512MiB称为应用总内存。
- 已执行存储事务继续 drain，排队和已授予许可取消均释放。零scratch交接阶段仍保留原owner生命周期。真正内容修订仍可重新规划；资源等待不变成整轮重派发。
