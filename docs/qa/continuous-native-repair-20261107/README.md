# macOS 常驻模拟账户来源修订验收

签名候选的产品源码是 `f1a789f3ace01633d5a7505d64b259bae0971d86`。两轮各 15 步均使用实际打包的 Electron、Python sidecar、应用界面和本地 API。上一轮已经跑通[独立研究窗口交接和常驻账户重启](../continuous-live-main268-20261107/README.md)，本轮以其中已正常停止、处理到第 38 根的模拟账户作为种子。

在两份隔离副本中，使用候选内置存储代码将原始输入窗口中的一根 BTCUSDT spot 1m BAR 收盘从 75923 修订到 76074.85，并保留来源日志和快照验证。QA 只更新副本中绑定数据库绝对路径的私有输入归属标记。原资料库文件逐一核验 SHA-256，候选在验收前后均通过严格代码签名验证。

| 操作 | 确认范围 | 完整退出后重启 | 两次退出耗时 |
| --- | --- | --- | --- |
| 修复并保持暂停 | 从原始起点重算 51 根 | 同一账户停在 51，界面与冷盘一致 | 2326、2996 ms |
| 修复后继续处理 | 从原始起点重算 53 根 | 同一账户以修复后的数据版本推进到 54 | 2414、2320 ms |

修复前，旧权益、仓位和序列在界面仍可读取。两轮均在明确同意后才提交一次修复，创建账户请求为零。重启后新增的第 54 根来自普通 Binance WebSocket，来源日志保留了原始 `k.x=true`。两轮最终均为 35 笔成交，独立空账户从同一起点重算，完整财务与策略状态匹配。导入行定位及未提供的可选指标按元数据归一，实际 BAR 值仍参与比较。原研究运行和报告未发生变化。

四次 sidecar 均以退出码 0 正常退出，无信号或强制终止，随后核实 42 条应用拥有的进程记录均已退出。首轮试跑的复制缓存仍绑定原路径，启动失败后仅终止该轮隔离进程。后续试跑发现另一处私有输入归属保护和验收脚本错误地沿用旧截止范围。保留这些失败证据，表中结果仅来自修正后的两轮。
