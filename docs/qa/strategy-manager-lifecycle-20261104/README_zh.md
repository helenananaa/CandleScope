# 持续策略的Manager所有权与应用关闭

基于#241（cb985fb2）内部后台会话；本范围不新增用户三模式或HTTP创建。DataManagerCore的StrategyDataManager可以显式接纳同一行情Manager、同一profile目录的唯一持续执行所有者；裸LOCAL_OFFLINE Core没有行情源，拒绝借别处的Runtime绕过。普通结果订阅/旧close_strategy仍只关闭观察者；应用关闭使用异步shutdown_strategy。默认构造不启动行情、不创建持续策略库。

应用正常关闭、后续启动失败的内层回收，以及startup_event外层失败处理，先drain持续执行/关闭其状态库，再停止插件、行情和固定历史服务依赖。Runtime.close将完整shutdown和数据库close作为一个不能被请求取消切断的拥有者收尾；源/Provider未退出或lease释放失败时，错误继续向应用传播，保留owner及开放状态库，不能继续把依赖当作已安全关闭。明确重试完成后才能继续。

close一进入便拒绝新启动并发出停止信号；setup在协程首步之前就被取消也会由Task完成回调回收容量，不依赖尚未执行的finally。正常shutdown依旧保存活跃phase供下次恢复；关闭已拥有的库放在完整物理drain之后。

56项实际Manager/Provider/SQLite/线程、应用shutdown与startup失败、LOCAL_OFFLINE真实子进程启动、订阅连续性及原StrategyManager组合通过，5条既有提示；架构与main原有10条逐字节一致。仅传输lease被替换以禁止远程连接，真实应用关闭入口验证Actor/lease已回收、SQLite已关闭后才停止backtest/data依赖。反复取消close后重开实际库，原检查点/账户和活跃phase保留。释放一次失败时实际应用停止依赖关闭，重试后成功。
