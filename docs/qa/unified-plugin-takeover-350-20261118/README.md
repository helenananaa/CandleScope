# #350 可信插件启动接管和恢复验收

2026-11-18，macOS arm64。产品源码 `7a07534c1`，验收样例与源码测试
`f1c6c4b9d`。两者之间只变更样例与测试。使用标准
`npm run desktop:package:dir -- --mac --arm64 --publish never` 构建，校验签名和
打包源码后复制到独立安装目录。四次启动共用一个全新的 LOCAL_OFFLINE profile。
包摘要、脚本摘要、ASAR 摘要和每步结果见 [原生回执](macos-arm64.json)。

| 场景 | 观测 |
| --- | --- |
| 正常接管 | 通过统一存储批准样例。回放 API 返回替换服务的标记，Electron 实际窗口挂载样例的 shell。源码启动测试还断言 DataManager 与回放运行时引用同一个 `TakeoverReplayService` 实例。 |
| 真实启动故障 | 同一包 ID 升级到故障样例。回放工厂按测试设计抛错，安装版写入启动错误，健康接口未就绪，后端退出码为 3。测试驱动终止了显示模态故障对话框的那个 QA 进程。 |
| 独立禁用 | 通过安装版的 `--disable-unified-plugin=example.startup-takeover` 启动。注册表持久记录包已停用，窗口和回放 API 恢复内置实现。关闭窗口后确认应用和后端都退出。 |
| 正常重启 | 同一 profile 无恢复参数启动，仍使用内置实现并正常退出。原版本与故障版本的归档仍可复核，私有 Pine 测试脚本的 SHA-256 前后一致。 |

首次运行暴露 POSIX 父进程管道读取导致的 Python 退出崩溃。独立子进程测试复现并覆盖
该问题，最终安装候选重跑上述四步，故障时留下原启动错误并以状态码 3 退出。

本地结果为 SDK 243 项、后端 106 项通过（跳过 1 项 Windows 专用测试）、桌面 145 项、
相关前端 71 项。通过 TypeScript、前端架构、插件边界、i18n、变更文件 lint 和生产构建。
源码测试覆盖冲突拒绝、受限包拒绝根布局声明、依赖者原子禁用、资源保留到退出以及 Pyne 拒绝。

本次安装版结果覆盖 macOS 的离线回放和主窗口 shell。live 模式的其余工厂、其他窗口的
交互验收和 Windows 安装版仍待验证。Windows 连接尝试两次均返回 429，未启动候选。

## Windows x64 安装版

GitHub Windows runner 的实际打包应用完成同一四步离线验收。故障包使后端以 3 退出，
独立禁用参数恢复窗口和回放服务，正常重启保持停用。原包及故障包仍可复核，
私有脚本摘要保持一致。[Windows x64 回执](windows-x64.json)。
