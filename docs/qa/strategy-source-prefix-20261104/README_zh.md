# 持续策略的源前缀保护（内部基础）

普通尾部追加不等于修订已处理输入；重启也不能只相信旧内存事件。已有D126全系列包络不当作精确编辑日志。本实现为消费者保存最多128条完整行情身份/from/through、incarnation及有限版本标记，通过物理SQLite触发器保护已使用前缀。没有逐行行情副本、逐事件日志或新哈希。独立watch版本不依赖SQLite触发器执行先后，不改变D126原clock语义。

所有入口均经DataManager.bars.prefixes；页面/策略不另读原始行情库或建网络连接。计算前扩展保护，发布时在短源写锁里验证版本，并调用已经准备好的同步财务提交；快照/计算/编码在写锁外。明确拒绝async回调被未await就确认。物理旧行修订/插入/删除及删除空范围被观察，正常尾部追加、其他商品及同名商品不同语义身份隔离。

财务提交失败保留原提交点；财务已提交但source ack前崩溃，保护前缀已先持久化，重启不会漏掉修订。有限verified字段区分未处理区间重取与历史修订，已确认财务/源采集代次还拒绝财务库或源watch回退。旧lease不能提交或释放新采集；watch丢失或incarnation不同明确未就绪。

99项真实SQLite/Manager/交付/缓存修订回归通过，完整后端架构与main既有10条逐字节一致。新增窗口边界用例先复现close_time收缩离开原保护范围时漏报，保留失败后改为保护OLD/NEW范围并集；未放宽断言。跨进程写、回滚、源写锁与独立财务SQLite真实提交、两个崩溃窗口及身份/容量均执行。
