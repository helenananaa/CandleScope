## 1. 结论与阅读说明

基础看盘链路可用：Binance 现货、OKX 现货与永续合约可以加载；周期切换、自定义 45m、15 种图表、常用指标、双图/四图、联动、绘图和部分图片导出均有实际操作证据。图表内 SMA 策略模板完成了一次真实回测，产生 175 笔完整交易，并能通过交易行定位图表。

目前影响使用的主要问题是：**页面可见区导出反复失败、浅色主题结果卡片难以阅读、快捷键穿透当前操作上下文、指标参数缺少有效校验，以及盘口/成交流异常时状态解释不足**。此外，搜索兼容性、窄窗口布局、专业数据的表达方式和新用户上手流程仍有明显改进空间。

本报告包含 **22 项具体问题/体验缺陷、2 项需进一步复核的观察、2 项性能排查线索**。优先级是本次建议，不代表项目已有分级：P1 为明显阻碍主要功能或读取结果；P2 为功能局部失败、交互歧义或重要体验问题；P3 为呈现、文案与便利性改进。没有确认到 P0。

“通过”只表示表中所列操作成功，不表示该模块所有组合、公式或边界均已验证。未将工具点击失败、首次缺依赖、动态行情短暂补载、尚未提交的绘图预览当成业务缺陷。截图中的实时价格只能用于复现当时状态，不构成行情正确性的独立证明。

## 3. 具体发现

### F01 · P1 · “页面可见区”图片导出反复失败

- **复现**：实时行情图打开“截图 / 导出图片”→ 页面可见区 → 2x → WebP；等待完成、重试。之后在 OKX 永续合约场景切换 PNG 再试。
- **实际**：出现“绘图在截图期间发生变化，已丢弃过期预览，请重试”，保存禁用。WebP 重试后仍失败，PNG 页面区域同样失败；过程中没有主动改动绘图。
- **期望/影响**：普通实时更新不应让用户无法导出当前页面。错误归因于“绘图变化”也不利于理解。需先定位页面区域捕获的一致性机制，不能简单归咎于 WebP 编码。
- **对照**：整图 PNG、主窗格 JPEG 已成功下载；因此不是所有截图功能都失败。
- **证据**：[WebP 重试](../../output/user-audit-20260907/evidence/37-webp-retry-result.png)、[PNG 错误文本](../../output/user-audit-20260907/evidence/109-page-png-result.txt)。

### F02 · P1 · 浅色主题的策略区域存在严重对比度问题

- **复现**：设置→亮色→保存；打开图表策略测试器→SMA 模板→运行，进入概览。
- **实际**：模板/源码/问题/结果区域混用深色背景与深色文字。净收益等信息视觉上几乎不可读；轻量诊断文字也难辨认。
- **期望/影响**：所有主题都应能直接读清结果和操作状态。当前不只是审美偏好，而是妨碍读取回测结论。
- **证据**：[模板](../../output/user-audit-20260907/evidence/70-live-strategy-template.png)、[概览](../../output/user-audit-20260907/evidence/74-strategy-result.png)。未测量 WCAG 数值，不声称具体对比度比例。

### F03 · P2 · 绘图选中时 Cmd+Z 撤销的是工作区布局

- **复现**：四图工作区改为双图→最大化第一图→画线、拖出矩形并选中→Cmd+Z。
- **实际**：矩形仍存在，布局从当前状态退回四图；Cmd+Shift+Z 又恢复到双图中的最大化状态。
- **期望/影响**：用户正在编辑绘图时，很容易预期撤销最近的绘图操作；当前全局布局历史抢占快捷键，会导致意外跳图和上下文丢失。若绘图暂不支持撤销，也应明确区分作用域。
- **证据**：[矩形选中](../../output/user-audit-20260907/evidence/90-rectangle-after-select.png)、[撤销后四图](../../output/user-audit-20260907/evidence/91-drawing-undo.png)、[重做](../../output/user-audit-20260907/evidence/92-drawing-redo.png)。

### F04 · P2 · 搜索弹窗的 Esc 提示与实际行为不一致

- **复现**：最大化图表→打开交易对搜索→通过右键打开添加菜单，菜单关闭后搜索仍开着→Esc。
- **实际**：搜索框仍在，背后的图表从最大化恢复双图；显式点击“关闭 (Esc)”按钮才能关闭弹窗。
- **期望/影响**：Esc 应优先关闭最上层弹窗/菜单，不应穿透到背景布局。至少该焦点路径与按钮承诺不一致。
- **证据**：[Esc 后弹窗未关闭](../../output/user-audit-20260907/evidence/99-watch-list.png)、[显式关闭之后](../../output/user-audit-20260907/evidence/100-watch-after-close.png)。未断言所有焦点位置均失败。

### F05 · P2 · SMA 周期 0 未被有效拒绝，暴露内部异常

- **复现**：添加 SMA→已添加→period 从 20 改成 0→移出输入框。
- **实际**：显示 `deque index out of range`，均线结果不可用；不是清晰的参数校验提示。改回 20 后恢复。
- **期望/影响**：拒绝非有效周期，并保留上一次有效计算；说明允许范围。普通参数编辑不应把后端实现异常直接展示给用户。
- **证据**：[异常截图](../../output/user-audit-20260907/evidence/22-invalid-period.png)、[异常文本](../../output/user-audit-20260907/evidence/22-invalid-period.txt)。仅验证 0，没有扩展声称负数、NaN 等全部失败。

### F06 · P2 · 常见交易对写法 BTC/USDT 搜索不到

- **复现**：Binance 现货、USDT 筛选→输入小写 `btcusdt`，再输入 `BTC/USDT`。
- **实际**：前者能找到 BTCUSDT，后者 0 条。
- **期望/影响**：常见分隔符应可归一化，或明确提示交易所使用的代码。否则用户会误以为不支持该品种。
- **证据**：[小写有效](../../output/user-audit-20260907/evidence/07-search-lowercase.png)、[斜杠无结果](../../output/user-audit-20260907/evidence/08-search-slash.png)。

### F07 · P2 · 盘口长时间等待，恢复路径与数据新鲜度不足

- **复现/观察**：Binance ETHUSDT 看盘过程中，主图与成交继续更新，盘口多次长期“等待第一份有效盘口”；切连续模式提示“盘口快照长时间未更新”，回快照仍等待。
- **实际**：约 13:35 的失败证据之后，13:42 左右最终自行恢复。日志出现 `CCXT stream failed (ETHUSDT@depth20@1000ms)`。这是间歇性问题，最终并非永久不可用。
- **期望/影响**：给出最后有效更新时间、具体断流/重试状态、重连入口及降级信息。单独的“连接中”无法帮助用户判断行情是否还能依赖。
- **证据**：[连续模式异常](../../output/user-audit-20260907/evidence/52-continuous-book.png)、[恢复盘口](../../output/user-audit-20260907/evidence/78-zoom100.png)、[运行日志](../../output/user-audit-20260907/backend.log)。网络、交易所或后端流处理的根因尚未隔离。

### F08 · P2 · 成交流等待与“实时连续”标签同时出现

- **复现**：OKX BTC-USDT-SWAP，主图和盘口有数据，保持成交/分布面板打开。
- **实际**：成交一直显示买卖 0 笔、“等待第一笔聚合成交”，同时展示“实时连续”。在本次约数分钟观察窗口未完成有效成交带加载。日志存在 trade 订阅取消、重连；depth 还记录 HTTP poll 降级，而底部仍以全局 WebSocket 描述行情。
- **期望/影响**：能力标签、当前传输方式和数据就绪状态应分开；不能让“实时连续”看起来像已获得连续数据的健康确认。并不据此判定该交易所永远无成交支持。
- **证据**：[导出时仍等待的状态](../../output/user-audit-20260907/evidence/109-page-png-result.txt)、[浅色合约页](../../output/user-audit-20260907/evidence/106-futures-stable.png)、[后端日志](../../output/user-audit-20260907/backend.log)。

### F09 · P2 · 自定义指标运行时不可用，错误没有可操作解释

- **复现**：指标→自定义→新建脚本。
- **实际**：显示 `Invalid indicator payload at indicator.runtimes.languages: unknown runtime id candlescope.pyne` 和“无法发现可用脚本运行时”，运行/保存不可用。窄编辑器顶部运行/保存文字还被挤成逐字换行。
- **期望/影响**：进入编辑前告知该平台插件不可用、所缺能力及可行路径，避免用户写完才发现无法执行。README 已声明第一方插件包当前面向 Windows，故“Mac 上没有此运行时”本身属于范围限制；不友好的协议错误及入口引导是体验缺陷。
- **证据**：[编辑器错误](../../output/user-audit-20260907/evidence/24-script-runtime-unavailable.png)。图表内置 SMA 策略回测成功不代表自定义指标插件已修复，两条路径不同。

### F10 · P2 · 插件页“2 个可用”与两个条目均“不可用”冲突

- **复现**：设置→插件与扩展。
- **实际**：标题写“已接入的指标语言运行时，可直接为图表提供计算与渲染能力。2 个可用”；pine、pyne legacy adapter 各自却标“不可用”。本地包上传文案还暗示可从上方选择，实际入口不可用。
- **期望/影响**：区分已发现、已安装、可执行、平台兼容数量；解释禁用原因。否则用户无法判断该修环境还是功能尚未支持。
- **证据**：[截图](../../output/user-audit-20260907/evidence/60-plugins.png)、[完整状态](../../output/user-audit-20260907/evidence/60-plugins.txt)。

### F11 · P2 · 策略结果显示原始长精度数值，胜率没有百分比表达

- **复现**：内置 SMA 模板运行完成→概览/交易。
- **实际**：胜率 `0.02857142857142857142857142857`，卡片截断为长小数；净收益 `-959.863449776 USDT`，交易价格、费用大量小数。最大回撤显示“— / 按已实现结果统计”，而页面又画出权益/回撤曲线。
- **期望/影响**：胜率应清楚显示约 2.86%，金额按合理位数显示并可查看原始值。回撤缺失应解释统计口径/不可用原因。此项是格式与口径说明缺陷，没有独立重算证明回测金额或曲线算法错误。
- **证据**：[概览](../../output/user-audit-20260907/evidence/74-strategy-result.png)、[完整结果文本](../../output/user-audit-20260907/evidence/74-strategy-result.txt)、[交易表](../../output/user-audit-20260907/evidence/75-strategy-trade-locate.png)。

### F12 · P2 · 双图/四图信息头和指标标签侵占图形

- **复现**：3 个指标（SMA、MACD、RSI）→四图；也可打开双图+底部策略测试器。

- **期望/影响**：按窗格宽度渐进收起次要指标值，悬浮/展开看详情；设定副窗格最小可读高度。多图需要单独的紧凑布局规则。

### F14 · P2 · 长合约代码挤坏顶部布局

- **复现**：994×768 测试窗口切到 OKX BTC-USDT-SWAP。
- **实际**：顶部代码断成 BTC- / USDT- / SWAP 多行，按钮高度增加；策略状态被截断，标记/指数/基差压缩其他入口。

### F15 · P2 · 导出面板在窄图格中失去“设置+预览”的可见布局

- **复现**：双图下打开导出；或单图打开导出并切换多个设置。
- **实际**：面板局限于当前图格，设置变成狭窄长列，保存按钮/预览落到当前可见区之外。文件名、尺寸信息也容易截断。单图早期可通过滚动找到保存并成功导出，故不是“永远不能保存”。
- **期望/影响**：关键操作固定在可见底部；空间不足时用整页弹窗或单列步骤。避免用户误以为功能只有设置没有结果。

### F16 · P3 · 导出图片默认缺少独立阅读所需元数据

### F17 · P3 · 中文界面存在技术字段、英文控件和 Emoji 风格混用

- **复现**：指标列表、参数、绘图工具、策略/回放页面、关于页。

- **期望/影响**：普通模式优先中文金融概念，技术字段放高级详情；统一图标大小、线宽、选中状态和字体。不是要求隐藏必要专业信息，而是让同层信息采用同一表达标准。
- **证据**：[指标](../../output/user-audit-20260907/evidence/19-indicators.png)、[参数](../../output/user-audit-20260907/evidence/107-futures-indicator-status.png)、[关于文本](../../output/user-audit-20260907/evidence/112-about.txt)。

### F18 · P2 · 启动失败与网络检测不能共同解释“为什么没有图”

- **复现**：本次缺少后端依赖导致数据管理器未就绪时，打开主图并运行网络检测。
- **实际**：主图加载失败，提示用户运行 `uvicorn app.main:app --reload`；网络页却显示 3/3 连接成功。
- **期望/影响**：网络可达和数据引擎可用不是一回事，应分项诊断；发行版故障不应默认引导用户开启开发热重载。提供可复制诊断摘要、重试与本地服务状态更有效。
- **证据**：[主图失败](../../output/user-audit-20260907/evidence/02-startup-degraded.png)、[网络全部成功](../../output/user-audit-20260907/evidence/03-network-success-data-fail.png)。缺依赖本身不计产品缺陷。

### 测量方法与结果

|---|---:|---:|---:|---:|

[静置 CSV](../../output/user-audit-20260907/perf-idle.csv) · [交互 CSV](../../output/user-audit-20260907/perf-interaction.csv) · [汇总 JSON](../../output/user-audit-20260907/perf-summary.json)

CPU 为系统进程采样口径，100% 大致相当于一个逻辑核心；不是整机占用百分比，也不是精确请求耗时。RSS 不是 JS heap，更不能与设置页“缓存估算 1.4 MB”直接比较。Chrome GPU、扩展、浏览器共享进程未计入此表，策略页可能共享站点进程，不能把 renderer RSS 全部当成看盘代码独占内存。

**实际体验**：缩放、拖动、切周期、布局切换能完成，没有捕获浏览器“页面无响应”或持续冻结。工具自动等待包含截图与辅助功能读取耗时，因此没有把 tool wall time 当作点击延迟。没有使用帧时间录制，不能给出 FPS、P95、输入延迟或宣称已定位具体函数热点。

### P-H01 · 后端历史补载/指标重算的资源峰值值得进一步定位

交互窗口后端 CPU 最大采样 96.9%，RSS 最高约 1.14 GiB；图表条数从约 1510 增至 2011。时间关联说明历史补载与指标计算链路值得剖析，但没有火焰图，不能断言具体耗时函数。短时内存上涨可来自缓存、数据集、计算中间结果，不能直接定性为泄漏。

后续可使用同一发行包，在固定数据窗口进行单图/双图/四图、无指标/三指标、成交分布开/关的分组采样；增加长时间回落观察及后端 CPU profile。此次仅记录建议，没有改缓存或节流策略。

### P-H02 · production 大块资源可能影响冷启动/功能首次打开

构建日志中的 `chartAppearanceSettings-DHmCgV-O.js` 达 2453.91 kB（gzip 698.86 kB），CSS 303.43 kB；DrawingEngineHost 445.55 kB，live 398.55 kB。Vite 发出大于 500 kB 的 chunk 警告。

这些是**产物体积事实**，不是已证明的运行热点。文件名不代表其内容全是外观设置，不能据此推断代码结构。下一步应测资源实际加载时机、解析执行和未使用比例，再决定是否拆分。此次没有做冷缓存网络时序或低配机器基准。
