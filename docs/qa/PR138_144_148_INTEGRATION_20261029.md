# History, revision and subscription recovery integration

PR #144 now consumes PR #138's durable revision fencing and shared memory
registry. Their combined tree has also been tested with PR #148's subscription
recovery. All three PRs remain Draft; this is an integration increment, not
acceptance of issues #126, #127, #129, #130 or #112 as complete.

## Changes

- Align #144 with main `5195d983` and #138 `8299ad5f`, retaining the current
  source/admission wiring, immutable bar records and retired Pyne rejection.
- Remove the private aggregate-block cache and its configuration from runtime
  wiring. Preserve the prototype, benchmark and correctness checks under
  `backend/scripts/experimental_aggregate_blocks.py`. It is not B130 and is
  not constructed by queries. Benchmark fixtures use the real compact decoder.
- Admit streaming work through the D126 `history-query` owner before the first
  source page. The reservation covers estimated page buffers, cross-page bucket,
  sparse output and quality summaries; nested reads share an outer work scope.
  The lease stays live through materialization and final revision validation,
  then releases on success, failure, budget rejection or cancellation.
- Preserve fixed-interval anchor phase in both streaming bucket boundaries and
  the canonical reducer. Keep range, before, native 3d and calendar routing.
- Verify real SQLite source corrections/deletions after the first page has
  already reduced: the request becomes pending, publishes no mixed result and
  cannot persist stale derived bars. A fresh request observes the new source.
- Preserve both history-staging and interval-admission browser fixtures after
  merging main. Wait for the committed browser document before invoking a
  fixture once, avoiding the initial-navigation context-destruction race.

## Remaining integration boundaries

Only #127 currently has an open implementation PR (#144); #129 and #130 are
issues, not existing implementation PRs available to compose. K130/B130 shared
blocks, the versioned H127 block/cancel interface and R129 realtime state still
need implementation and joint acceptance. No second shared block owner or
realtime state owner was introduced here.

The memory allowance is deliberately conservative and may defer large requests;
it is estimated admission, not measured RSS or a full process-memory ceiling.
Results and the last incomplete bucket remain bounded in memory. The complete
resource/latency matrix, actual source coldness scenarios, native restart/UI
recovery and long-running exchange recovery remain outside these test results.
