## 异常恢复的新增缺陷

同一候选的后端 SIGKILL 测试能显示断线并禁用命令；退出后重开，资金、订单、成交、账本、虚拟时间及绘图一致，并能继续推进。但手动重新同步清空旧 snapshot 后，页面只剩恢复动画，隐藏了 store 中的连接错误。修复后，未取得新权威 snapshot 时保留错误与重新同步入口；沿用原 resync，不改变不确定命令的同 ID 对账路径。

仅强制结束桌面主进程时，Python 已完成 Uvicorn lifespan，但仍等待网络工作线程。45 秒后仍残留后端及 resource tracker，已保存进程采样与人工清理记录，不能记为自动退出通过。后端现在在私有 stdin 收到关闭命令或 EOF 时保留 15 秒清理时间，超过期限写入明确错误并退出码 1 强制结束自身；不作用于普通服务器入口。该期限与桌面宿主已有清理上限一致，属于异常兜底，不等同于优雅退出成功。另修复被信号结束的 sidecar 仍显示 running、关闭时等待第二次 exit 的问题。

三个回归均保留修复前失败记录。当前本地回放前端 615 项、sidecar 后端 14 项（另 1 项 Windows 专用跳过）、应用/回放/插件关闭集成 30 项通过。新增 sidecar 模块加入 ARM64/x64 随包门禁。修复后的远端 CI 与统一包故障重测尚待执行。

原始主进程崩溃存档重开后，65 条账本及完整账户/审计一致。一次 QA 比较失败来自采集顺序：先读 tracks 得到上一轮 59 条账本的审计摘要，再读 report 触发当前审计；崩溃前 report 与重开 report 的完整账户、审计及哈希完全相同。原始失败与出处保留，后续采集改为先审计再取 tracks，没有排除或改写账本。
