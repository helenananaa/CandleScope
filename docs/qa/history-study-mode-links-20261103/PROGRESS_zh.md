## 产品行为

模式和游标是两个独立、默认关闭的联动选项。仅联动模式时，目标恢复自己的已保存输入及游标；尚未准备输入时明确拒绝，不复制源图的数据或新建研究。同时联动游标才使用源图的绝对 UTC 时刻，越界拒绝、不静默钳制。正式回放/策略运行的时钟、账户和账本不进入这套轻量研究联动。

事件必须经过主进程统一排序，并匹配已提交的有效联动路由；无关布局持久化不能无故阻塞有效事件。工作区 A→B→A、替换源端口、目标输入更换、路由关闭后重开，以及迟到的异步排序回包均有回归测试。配置变化取消中的操作时保持“尚未确认”提示；模式失败与游标成功分别管理。活动研究的重试在研究页脚，退出后的重试在行情加载遮罩之上，均通过实际按钮点击验证。

1. 默认关闭模式联动时，两窗口三份已有研究维持各自游标，第四张图保持实时。
2. 开启模式联动后返回实时；恢复源研究时，目标各自恢复自己的固定输入与游标。源、同窗、跨窗游标分别为第 25/100/120 个已揭示细数据收盘；来源笔记显示各时刻有效版本，未来版本隐藏。
3. 目标实际 PATCH 已提交但响应仍挂起时，目标先进入恢复遮罩、显示 0 根 K 线，不短暂暴露实时数据；之后中断该响应，经实际权威读取恢复。
4. 无输入的第四图明确失败；一次成功游标动作不会抹掉模式失败。通过实际 UI 单独准备该图自己的 5m 输入，再重新加入分组和点击重试。
5. 分组并发变化留下可见的未确认状态，按最新保存配置实际点击重试。目标笔记编辑器打开时拒绝模式退出；其他两张图可退出。该图控制接口按设计报告 busy/输出未就绪，游标不动。关闭编辑器后，在实时源图上点击重试使其恢复。
6. 同时启用模式和游标，四份独立输入在同一第 25 个细数据收盘投影；各图实际 OHLCV 与独立细数据聚合一致，SMA20 最大浮点误差约 `1.46e-11`。

## 失败记录与验收脚本纠正

完整保留失败证据，不能把失败或未启动候选计作通过。`config-native` / `lifetime-native` 仅组装、没有启动；只有 `final-native` 为最终通过。

- 最初直接复制准备缓存所有者，生产代码正确拒绝 `CACHE_OWNER_MISMATCH`；启动失败还记录了 Python daemon stdin finalization 异常。最终克隆脚本保留原停止的受控资料，排除派生准备缓存/数据库、插件安装目录、控制连接，由正常所有者创建新目录；不重写 ownership 标记、不弱化检查。
- 清理最初启动失败时，CUA `getApp` 意外另开了一次使用默认用户 profile 的同一候选，随后正常 Cmd+Q 退出且核对候选进程全部结束；没有执行账户/订单命令。这次启动排除在所有验收主张之外，详见 `startup-failure-cleanup.json.gz`。后续只用明确的自有 profile 和 loopback 沙箱启动，不再调用 `getApp`。
- 原生验收依次暴露并修复：配置传播未确认的跨窗退出、活动研究重试被侧栏遮挡、配置变化取消操作却没有提示，以及实时加载遮罩拦截退出后重试。
- 两次后期失败属于脚本错误：打开编辑器时要求 busy=false / computing=false；实际控制契约故意将输出标为未就绪。最终只修正断言，不强制点击、不绕过遮罩、不改变产品就绪条件。
- 另一次包内测试脚本误用 `app.history` / `app.trading` 导入路径，先保存导入错误日志，再核对实际模块路径，修正为 `history_studies` / `trading_accounts` 后运行真实 73 项测试。
