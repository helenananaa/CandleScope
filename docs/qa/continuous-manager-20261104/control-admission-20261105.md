# Account identity at control admission

Source `c28754fd` fixes a race found during Manager/lifecycle review: the Manager checked the full financial identity, then called Controller control, which rechecked only the creation revision. A pause and resume between those two steps could leave the creation revision unchanged while the financial account moved to a newer generation. The late request could then stop or control that new generation.

The Manager now forwards the confirmed full identity. After acquiring its exclusive action slot, the Controller rechecks its shape, exact field types and complete identity before stopping actors, cancelling repair or starting execution. The existing early Manager validation remains. Private Controller calls without an identity retain their existing internal behavior; public committed-account control still requires the full identity. Preparation controls remain tied to creation revision and reject a financial identity.

Four new counterexamples use actual SDK Python/SQLite/Controller/Runtime. After the Manager checks the old identity, real Controller pause and resume complete before the original pause/cancel/resume/retry request is admitted. All four fail the old implementation. With the fix, every old request returns `CONTINUOUS_COMMIT_CONFLICT`; the new-generation complete account is byte-for-byte logically unchanged, its Actor remains active, and final shutdown releases leases/Controller resources.
