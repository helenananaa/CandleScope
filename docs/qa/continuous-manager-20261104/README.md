# 常驻策略 Manager 与应用所有者

基于 Draft #251；应用提交 `6d99286af8eb8d27110507fd905bc10796243d1f`。

## 应用生命周期

应用在固定历史服务及 StrategyDataManager 绑定后，默认打开同一配置目录的 `continuous-strategy.sqlite3`。沿用 `BACKTEST_BAR_ENABLED` 的有效资格；不额外制造用户策略版本、smoke 记录或输入身份。

LIVE 中仅绑定本应用实际采用的 DataManager，再恢复已提交运行/准备意图；原始暂停继续保持暂停。同一 Manager 重复初始化返回第一次初始化状态，不重新启动后来被明确暂停的账户。市场对象不可用或身份不符时，不接管它；私有目录归属不明则降级功能并保留原数据。物理清理不完整仍抛出，由应用在市场依赖之前重试关闭。

LOCAL_OFFLINE 打开无市场对象的保存资料所有者，仅允许读取；不恢复执行、不创建数据需求、也不通过公开控制面修改续跑意图。响应明确包含配置模式和 `execution_enabled`，不会把持久化 LIVE 意图误称为当前正在执行。配置模式在所有者构造时固定。

StrategyDataManager 关闭时先停止生产者，排空启动、控制与视图 I/O，再关闭 Controller 的账户/来源/Provider 和 SQLite。DataManager 直接 shutdown 也改为等待该过程，补齐了原来只同步关闭视图的路径。LOCAL_OFFLINE 启动异常同样先处理策略所有者，再关闭历史服务、插件和本地数据依赖。

## 有界访问与订阅

- 接受最多 8 个并发外部请求；视图 I/O 使用两个专属线程和有限待处理预算。创建/控制请求和已提交读取的调用者取消后，实际后台任务仍占有容量直至结束。相同旧账户的索引准备合并为一个任务。
- 固定历史与常驻订阅共享默认 32 个观察者上限。订阅只持有 coalesced 更新通知和一页结果；断开视图不停止账户。心跳不读取数据库。
- 准备阶段只读小摘要，不反复解码代码或初始化输入。正常历史初始化未到首次截止点时只推送进度；完整初始结果可用后，再发送有界 snapshot 分块。
- `begin` / `complete` 标识一组结果；只有整组完成才推进 `after_checkpoint` 基线。后续提交按合并变化发送 update 分块；分页中版本变化发送 reset，调用者丢弃尚未封存的组，再接收新的 snapshot。它不是不可变逐笔事件日志。
- 停止、失败、待修复、暂停继续可观察；终止账户的保存结果先完整分块发送，再结束订阅。每页仍沿用 #251 的 100 条订阅页（读取硬上限 200）、1 MiB 结果预算和完整提交 identity。
- 已有账户的控制在准入时校验完整观察 identity，拒绝陈旧或不完整的请求；停止需等待 Actor 退出，再在最新安全提交点改变 phase。确认同时返回创建摘要和实际 run 状态，不把创建日志的 COMMITTED 当作暂停状态。

## 证据

`manager-full.log.gz`：策略/账户/来源/执行器/应用关闭回归，加固定历史 Manager、DataManager 域/GC/预热、完整离线应用和插件生命周期，合计 **408 passed / 5 既有 warnings / 0 skipped**。不是全仓库检查。

其中 16 个访问场景覆盖 builtin/Python × 两种模式、同解释器中全新 Manager 自动恢复原账户且保留成交前缀、明确暂停不自动恢复、离线读取原保存账户且不改变意图、陈旧控制不停止 Actor、心跳和共享容量回收、请求取消/并发上限、读取中重复取消关闭、启动绑定前取消、私有数据归属/市场对象错误。

分块场景在 300 根初始发送期间推进到 301 根，验证 reset 后完整重建；再一次追赶到 801 根，验证多页 update 一致且没有重复成交。初始化场景在处理到 1000/1500 根时暂停，验证只推送进度、保留财务检查点，明确恢复后完成剩余输入与结果。

两个现有 LOCAL_OFFLINE 应用测试运行完整 FastAPI 子进程。新增断言验证默认只读 Controller 没有 Actor/准备任务，退出上下文后 SQLite 与配置锁真实关闭；该完整应用场景使用新配置目录。带已有账户的离线读取/意图保留由真实 Manager 分层场景验证，未把它们合称为原生 LIVE 进程验收。

首批旧回归 186 项通过；新测试文件第一次因辅助函数名 `setup` 被 pytest 识别为 xunit 初始化而产生 9 个收集/准备错误，改为 `access_setup` 后 9、15、17 项场景逐步通过，最终集合通过。原错误日志保留于 `manager-focused.log.gz`。

架构检查返回既有 10 条，与 main 基线逐字节一致；见 `manager-final-architecture.log.gz`。前端未改，没有运行其全检查。本轮没有组装/启动原生包、公开行情或 Windows 产品验收。

## 剩余交付

CI 后台运行，合 main 前核对最终 head。原生 LIVE 验收继续遵守全局公开行情冷却，不能用这些本地/离线证据替代安装包保存、完整退出和重启。
