# Packaged research handoff and live strategy restart

The macOS arm64 candidate at `f1a789f3` includes main `ed34833c` and pending #269 `c03dd269`. It uses the complete current tracked backend and SDKs, a fresh frontend build and source-verified reused runtime dependencies. Before and after acceptance, the strict signature passed. The package manifest matched 1,077 source files, 172 built assets, nine plugin assets and 76 plugin source files.

Three defects surfaced in the actual application. Saved research runs without a chart draft were hidden by the history filter. The desktop profile store rejected the frozen-version reference, and returning from a separate research window would focus the live window without delivering that reference. Finally, a source close could arrive before the local minute boundary, consume its wake, and wait until the following source close. The changes restore draftless history, admit a bounded reference namespace and route the reference to the existing live window. The strategy actor schedules one wake at the existing local boundary after an early final BAR, and cancels it with the actor.

The early-close counterexample first timed out after the actor observed the source event without advancing its cursor. With the fix, it advances at the local boundary without another source event. One combined backend run passed 600 tests, with two Windows-only skips and five existing warnings. The full frontend check passed 4,943 regular, one performance and 132 desktop tests plus production build. The frontend tree is identical between the check source `cdb56505` and packaged source `f1a789f3`.

The final 17-stage acceptance used a fresh isolated profile and a completed synthetic research run produced by the bundled runtime from a formally imported 20-bar CSV. The separate research window opened the real saved result and sent its frozen version to the existing chart window. Choosing the target created an independent chart draft. Starting the account required a fresh Python confirmation and sent exactly one creation request with the frozen program, parameters, starting minute and initial balance. The new account used ordinary live Binance spot BAR inputs for BTCUSDT 1m.

The cold witness after the first full exit recorded sequence 37 and 26 fills. The same profile and account resumed automatically, advanced to sequence 38, and retained the full 26-fill prefix with one appended fill. The confirmed input arrived 386 ms before the local boundary. The runner observed its committed result 110 ms after that boundary. The restored chart view matched cold SQLite at sequence 38, equity 4996.767634797863040988438763 and zero position. Both normal exits returned sidecar 0 with no signal or kill requests, and all 23 app-owned PID entries were independently absent. The original completed research run and report matched the seed after each cold read.

The first seven attempts and their shutdown records are retained. QA corrections covered the run list response envelope, a missing restorable dataset in the first fixture, closing the research drawer, and matching the strategy toolbar label after restart. The penultimate attempt also provides a separate actual backend restart witness, from sequence 32 to 33 with the unchanged fill prefix, and the observed one-minute lag. It failed the UI selector and does not count as end-to-end acceptance.

This qualifies the selected-version and ordinary LIVE resume flow on this local macOS package. Native source revision repair, other platforms and a standalone installer remain open. Only closed reproducible pytest scratch was removed. The fixture, current and previous apps, Native profiles, and raw receipts are retained. See `receipt.json` for commands and hashes.
