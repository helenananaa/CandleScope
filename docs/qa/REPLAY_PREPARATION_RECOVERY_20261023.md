## 原生发现与修复

使用 #83 的正常 ARM64 包、全新 profile/data、默认 GC，首次创建 LTCUSDT spot BAR 训练。开始时间为 `2026-10-10T07:59:00Z`，预热 200 根，向前准备 1 天，展示 1h，ONE_WAY/CROSS、APPROX_PROXY、无盘口及资金费。

首段 456 根已发布，任务在 1/3 时失败，错误为 `NO_SETUP_COMPATIBLE_SOURCE_MARKET`。日志中首次 Binance spot 身份目录加载数量为 0。空历史加缺失身份资料的自动化用例复现了同一错误；这里的结构准入失败没有正确表达尚未准备好的身份依赖。

候选在创建 Run 之前按所选市场加入 Host 已有的目录刷新单航班，保留 TTL、失败退避及交易所冷却。资料仍缺失时返回 `INSTRUMENT_METADATA_UNAVAILABLE`，沿用准备任务的有界持久重试，复用已发布数据；不从商品字符串自行制造账户身份。已经绑定首个商品的 Run 先按原幂等路径返回，不因离线目录缺失重新获取资料。Run 已提交但首个商品尚未绑定时，恢复仍需补齐身份依赖；此处通过渐进/整段两个先红后绿用例复现并修复。

另一个原生问题是 FAILED 后创建窗口仍显示“正在准备历史数据”与“关闭页面后继续准备”。候选按照真实任务状态显示需要处理、已取消或已准备好，并保留准备错误码。

故障基线通过“继续准备”恢复为 READY 3/3；真实训练可显示 201 根 K 线、从 07:59:00 推进至 07:59:59，再保存返回大厅。第一次失败与重试之间做过只读 catalog 探测，因此这个重试不作为完全无探测的首次成功证据。最终包必须另用新目录验证。
