## 历史复现与验证

第 35 版研究页，自带 Python SMA / BTCUSDT spot / 5m / 初始 10,000 / 1x / 10% 仓位。Run `bt_9e3236362ad14c34b5cafa1e63ac2b09`，初次开仓 1 BTC × 85,343.213468，手续费 85.343213468；629 次成交、0 拒单，最终权益 -41,936.099802986380817。证据与 F44 共用 `qa34-v35-sma-*.json`、`QA34-v35-sma-completed.*`。

原因：SDK `TargetPosition(quantity="1")` 明确定义绝对数量；Host 只对 SIGNAL 应用 sizing 策略。当前教学模板输出绝对 1 个币，却让 UI 10% 仓位看似有效。与此同时 CRYPTO_SPOT_STANDARD_V1 的 account_model 是 LINEAR_PERP_ONE_WAY_V1，旧估算账本不约束可用现金或做空，max_leverage 默认也为空。

修复要求：

1. 保留 TargetPosition 的绝对数量契约；新教学模板使用方向信号让 Host 执行所选资金规模，不能暗改用户旧脚本。
2. 为新的标准现货运行提供明确的现金账户：不做空、不借款、手续费计入可用资金，待成交订单占用与价格跳空后的实际成交均检查，拒单和部分成交有可审计结果。
3. 版本化新预设/账户身份；保留旧 Run 及报告作为历史，不改写旧结果。现货不接受杠杆/资金费等不适用条件。
4. 自动验证现金/资产/权益、开平仓及费用、超额买入/卖出、并行挂单、跳空、部分成交和恢复；原生重跑自带模板并独立核对账本。
