# F20c：下载成功后仍无法创建回放训练

## 复现与根因

发行构建 `127.0.0.1:15173`、无 reload 的生产后端。在 F20a 的“准备历史数据”入口下载 OKX 永续 BTC-USDT-SWAP 1m，自 2026-09-06 00:00（本地 UTC+8）到任务封存终点，任务 `job:448e1c07-5b88-44bf-8422-aaa07f6383c8` 显示 SUCCEEDED、1/1 READY、3345 根。返回训练仍为 0 个可选商品。

手动下载写入实时 SQLite 库；默认 ReplayService 读取独立、不可变的 Parquet 回放归档。两者只是仓储接口形状相似，并不共用数据。因此 F20a 只有入口和返回动作，缺少真正的数据转换。隔离归档实验确认同一批数据转换后能产生 1706 个合格窗口。

实际接通归档后还发现训练能力缓存保留归档前的 `REPLAY_BAR_HISTORY_EMPTY`，即使目录已出现商品仍禁用创建。此状态刷新属于同一个“数据准备返回训练”闭环。

## 修改

- 成功任务的近期列表显示品种和周期；包含 1m 数据时提供“生成 1 分钟回放归档”。明确说明下载与归档是两步、每个任务最多 25 万根。
- 新增受手动下载功能开关保护的 `POST /settings/storage/manual-downloads/{job_id}/replay-archive`。仅接受 SUCCEEDED 任务的 READY 1m 目标，读取任务封存范围，逐根检查时间格与 close_time；覆盖丢失、释放、缺口、重复、超限均拒绝。
- 使用现有内容寻址 Parquet writer、归档互斥锁与原子目录发布；保留 `local_manual_history_snapshot` 来源，绝不冒充交易所校验归档。ReplayService 的读路径仍只依赖回放归档。
- 同步路由在线程池运行；进程内并发导入直接返回 busy，避免请求堆积大批库存快照。先校验本次全部目标，再开始发布。
- 能力接口标明本地导入是否可用。远程归档为只读；回放关闭或缺少已声明的 Parquet 依赖时不可导入。
- 返回或重开新建训练时同时刷新能力和目录，保留训练草稿。九种语言更新操作说明。

## 验证

- 后端 48 项通过：新桥接测试、手动历史 API、现有回放归档测试。覆盖空目录→合格窗口、重复导入不重复历史、实时库存变化不改变已有 revision、源数据失效及并发/开关拒绝。
- 前端 37 项通过：手动历史表单、文案和训练 Hub。新增回归验证归档前后能力由 disabled→enabled，且名称和预热设置保留。
- `npm run typecheck`、针对性 ESLint、`npm run build`、`git diff --check` 通过。构建仍有既存大 chunk 警告，不据此宣称运行卡顿已修复。
- 电脑操控真实生产构建：成功任务点击归档，显示“3345 根 K 线”；返回后 0→1 个可选商品。只读目录 API 确认无缺口、1706 个合格窗口。
- 在能力刷新修复后的最终构建创建 `QA-F20c-归档衔接验证`，Run `07eccba166ef444d8dc268a0725a278f`，手动起点 2026-09-06 23:45 UTC；商品选择页 BTC-USDT-SWAP 可用，选择后进入真实回放。
