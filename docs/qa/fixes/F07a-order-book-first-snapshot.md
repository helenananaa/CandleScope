# F07a 首份盘口无限等待

明确原因：订阅确认会解除命令超时，但首份盘口到达前没有新鲜度定时器。若上游持续没有有效盘口，状态会一直停在 connecting，现有 stale 状态的重试入口也无法出现。

修复：订阅确认后即启动已有盘口超时监测。首包未到达时超过阈值进入 stale，使用已有提示和重试按钮；有效数据到达后恢复 live。快照模式继续周期性监测，连续模式收到首包后解除该首包定时器，后续继续由服务端连续深度状态管理。

验证：

- 盘口测试 10 项通过。新增快照/连续模式首包超时、迟到数据恢复、定时器清理回归；相关 ESLint、Production build、git diff --check 通过。
- Mac 解锁后电脑操控发行版：刷新和切换 5 档重新订阅，能收到真实 OKX 盘口并进入实时状态。本轮未持续复现超过阈值的首包延迟，超时路径的证据为上述确定性回归测试，不声称界面实测覆盖该分支。
