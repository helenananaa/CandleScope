## Problem and behavior

Each imported dataset already has its own source ID, revision and immutable BAR rows. The former same-exchange filter hid a second imported dataset, account admission rejected its independent ID, and secondary actor preparation reused the primary source ID. Exact main's checked source reproduces the scope rejection and lacks explicit import-unit options (`evidence/main-before-feature.json.gz`).

CSV import now accepts an optional quantity asset and price quote asset, in both synchronous and background routes and the existing library form. The declared volume unit is the quantity asset. Both declarations are required together and participate in the immutable data epoch; symbols are never parsed to guess assets. A revision retains its dataset's established units, including when older import clients omit the new optional fields. Changing units requires a new dataset. Legacy unitless imports retain their existing single-market approximate replay.

Multiple local BAR datasets may share a simulated account only with declared units and the same settlement asset. Dataset IDs remain distinct in catalog, track, actor, history, note and checkpoint identities. The production local path requires an authoritative track plan rather than a browser-declared quote asset. Preparation uses each track's actual source ID. Online cross-venue and settlement restrictions remain. Missing local coverage is reported directly: neither frontend fallback nor backend preparation converts an imported source into online acquisition.

Native testing also exposed a real existing Review interaction defect: a recreated per-chart Review object reopened the integrity drawer on ordinary note-history interactions, covering the next control. The drawer now opens for the semantic review-session identity, rather than each object replacement. The failing native receipts and visible screenshots are retained; the driver uses real clicks and never forces a click through the covering panel.
