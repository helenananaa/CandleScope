# Pine 实时范围投影

产品源 `153b661f13070a3e65a1d47f10fb440d232a373c`，main `b442555d582dc0bb473bad92ac5e699efdaa78d5`。Pine bridge 在变化范围中声明有序时间记录。宿主对已声明的序列二分查找范围，范围外的公共点不转换成 wire 对象。通用插件仍保留原有的逐点筛选，完整快照保持原形状。绘图对象场景仍整体替换。

70 项聚焦、1133 项组合后端和 12 项前端测试通过。组合后端有 1 项 Windows 专属跳过。架构检查通过。范围测试逐字段对照旧逻辑，覆盖负偏移、空替换、逐点颜色、填充和绘图对象。

## 同输入实测

两组使用当前源码、同一固定 Pine core 和确定性源，均保留 IPC 增量。对照组在宿主解析后移除有序声明，从而走现有范围构建。每组 24 次观察，排除前 4 次。两组最终投影指纹一致。

| 历史 BAR | 每次公共点转换 | 宿主构造范围中位 ms | 发布至 ASGI 客户端 P95 ms |

| 1,000 | 1,001 → 1 | 0.415 → 0.045 | 14.21 → 13.85 |
| 10,000 | 10,001 → 1 | 3.138 → 0.049 | 20.76 → 12.32 |

4 万根在测试实例上提高 DataManager 查询上限到 5 万。SDK 接纳 splice 时仍可能复制前缀。绘图对象场景、浏览器绘制和 4 万根默认生产配置仍需独立测量或验证。

## macOS arm64 签名候选

重建 Pine bridge wheel，核对 engine 和 SDK wheel 与前一签名候选按字节一致。首次组包调用了缺少构建依赖的系统 Python，切到既有测试解释器后通过。真 Binance BTCUSDT 现货 1m 验证旧时间点上的增删、标记与背景色，来源修订后验证新 generation 和界面提示。脚本保存后完整退出并重启，两个 sidecar 均正常退出，重启前后分别取得 27 和 43 条真实有序范围帧。重启后的收盘边界再次返回 `INDICATOR_CALCULATION_ORIGIN_REQUIRED`，全流程未通过。独立冷读确认该根 K 线已入库，仍需区分查询、owner 准入及 runtime 回执的错误来源。Windows 原生与独立发布安装包单独验收。
