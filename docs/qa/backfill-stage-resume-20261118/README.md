# #447 资源等待后续跑原阶段

本次按用户指定范围交付：内存/执行器暂时无容量时等待真正许可，取得许可后继续原协程、原计划和原阶段；不将资源等待变成整轮重新规划或普通失败重试。产品提交 `10ae0b9f3bbf691d159b7b0e8dca3465b310f6dd`，叠加 #473，未合并。#447/#463 的冷库净≤3秒与完整生命周期仍独立验收。

## 实现与边界

- `BoundedExecutor.admission()` 在唤醒前原子保留 workers+pending 的实际容量；普通同步调用仍保持 fail-fast。等待者不占物理工作线程，取消或关闭会撤销未执行许可，已经执行的存储事务仍等待结束。
- `MemoryBudget` 为每个阶段颁发有界工作集，页缓冲和计算临时值从已授予额度借用；实际执行包络确定后，在同一协程中等待扩容。分阶段安全准入避免多个 planner 各持一部分内存却都无法执行；活跃任务扩容先于旧工作重开。没有提高默认 owner 64MiB 或全局预算。
- scheduler 在资源等待期间停放逻辑 worker。许可到达后恢复 continuation，不重新调用 engine，不增加派发次数，不再次消耗上层 token。生产默认无整轮并发槽；显式正值的嵌入配置保持逻辑上限并原地等待，防止持有下层许可又等上层槽的互锁。
- 原始页可由仍在执行、已取得完整工作集的其他订阅者继续采用。真正配额延期/视图重规划退出一次 engine 时释放该订阅者的内存引用，避免待重试任务用旧原始页占住其他任务所需的额度。取消原订阅者不取消其余消费者仍需要的物理获取。
- 合格 Binance spot/USD-M、原生固定网格、完整闭合 REST 页可从**既有来源日志**恢复全字段与当前 selected receipt；不另设持久缓存、下载器或 writer。恢复保留 initiating acquisition 的删除 floor，来源日志权限过期、缺行、非默认 identity、WS 选择或不支持的合同回到原获取路径。事务内修订/删除校验继续生效。未知合同的原始页退出后可能需要重新获取，不宣称通用零重复下载。
- 原生并发回归暴露既有 raw journal 首次升级 `provenance_json` 的竞态；新表直接带列，旧表在原 SQLite writer 锁内二次检查迁移，避免数据库升级错误误触发重复 HTTP。
- 真正内容修订冲突仍可重新规划，真正交易所配额仍按原 owner 延期；删除、身份和 owner 失效不获得新许可。本地等待、规划与修订重试仍计入净耗时。
