# #149 原生 OI 本地优先试点

产品源码：`0f4d53ed31530e59d5c9ea51a9c5d08c1e8808a3`。基于 #216（已纳入 main #211），只交付有界 `binance/futures` OI 历史最小闭环，不关闭整个 #149。

## 方案判断

[Binance 来源文档](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Open-Interest-Statistics) 明确允许无成交周期没有记录，并把 timestamp 定义为周期结束时间；没有承诺 UTC 对齐。最初的固定网格原型虽然测试通过，仍被否决；代码差异和日志保存在 evidence/rejected-grid-*。正式方案不推断每个格点必有样本，不补零，也不把空查询当成永久上市边界。

覆盖依据是成功且完整解析的有界查询回执。回执由现有 MarketMetricsRepository 在已提交数据匹配响应后写入，包含来源政策版本和行摘要。后续读取在同一 SQLite 读事务中核对数据与摘要；删除或修改会使旧回执失效。没有新下载器或另一套全局库存。达到上游页容量时不假设升降序，按时间二分，有工作预算。

原生 OI REST 历史时间戳原先也被向下分桶，现保留原值；实时临时采样沿用原规则。旧行全部保留，旧正式行与新响应冲突时返回部分/未知，不能自动升级资格。如何识别和协调既有舍入行仍需 #126/质量迁移方案。

## 行为

- `local_only`：只读，不补取或隐式写回。
- 默认 `fill_missing`：仅查询未取得合格回执的区间；有回执的正式历史跨服务重启复用。
- `refresh`：显式有界重查。当前只为本试点提供完整刷新语义；hybrid funding 显式刷新返回不支持，继续使用其原 owner。
- 尾部策略：最近两个周期按 60 秒回执期限重查，这是应用复用政策，不宣称来源永不修订更老历史；更老修订由显式刷新采用。前端收到期限后会重新评估。
- 同请求共享任务，重叠请求在同身份提交后回读；一方取消不取消另一方，最后释放或关闭回收任务。去重限当前进程。
- API 返回证明范围、缺口、排除范围、分页和重查期限。前端按范围接纳，部分失败不吞掉已证明范围；未知页最多自动尝试三次，可手动重试。超来源范围展示说明并保留本地数据。

## 证据和边界

143 项相关后端测试、81 项高级行情前端测试、类型/架构/改动文件 ESLint 与生产构建通过。涵盖真实 factory/normalizer/durable writer、SQLite 重启、本地只读、非对齐时间、空查询、范围补取、刷新、摘要失效、保留期、分页/工作预算、取消及原生响应结构错误。

`benchmark.py` 对主线 1988a9b8 作同输入受控比较：相同 100 条正式样本，1 次冷读 + 50 次热读；真实 factory/normalizer、SQLite、durable writer，HTTP 由计数桩替代，无外网。预热共享 registry/normalizer 后，调用数 51→1，写入行数 5100→100，结果一致；热读 P50 4.06→1.96 ms，冷读 4.45→6.83 ms。该延迟不代表真实来源或原生产品。首次未预热的对照同时保留，但不能用其冷读/CPU差异作性能结论。
