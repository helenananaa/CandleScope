# 首商品规划阶段目录版本冲突修复

正常 X 安装包在原生新建 HEDGE / CROSS 5x / AGG_TRADE 训练后，选择已有官方归档的 LTCUSDT 时反复返回 `CATALOG_EPOCH_MISMATCH`。界面自动刷新目录并清掉错误，训练一直处于尚未选择商品状态，未进入混合输入确认。原生开发者工具的响应及请求版本已留存；独立新目录规划请求能返回可用的 HEDGE_HYBRID 输入。该现场未下单、未推进，不计双商品持仓或风险验收通过。

首商品的披露规划现在仅在目录版本冲突时刷新并重试一次，并将刷新后的同一交易所、市场类型、商品及目录传给确认和选入阶段。商品消失、基础周期不再可用、其他错误或再次冲突都会停止；不会换商品或无限重试。耗尽后的错误保持可见，允许用户显式刷新。

正式选入仍按已有边界重新规划。若期间从完整输入变成混合输入，必须先返回界面显示 HEDGE_HYBRID / funding OFF 披露并取得明确确认，随后才选入。后端时间、目录、数据来源、账户和财务校验保持严格。

验证：原代码的“首次规划过期后应显示确认”回归明确失败；修复后 Hub 40 项通过。完整前端检查通过 4290 项功能、独立绘图性能用例和 102 项桌面测试，以及架构、插件、30 语言、类型、lint 和生产构建。生产 React 组件经浏览器实际点击验证了首次规划重试、重试耗尽错误持续可见、正式选入发生新降级后三种路径；仅 HTTP 边界被模拟，不能替代真实原生包资格。
