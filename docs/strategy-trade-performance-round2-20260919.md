# 成交策略测试：第二轮性能优化

在第一轮未提交修改上继续，仍在 `CandleScope-strategy-replay-performance`，基线 HEAD 为 `172ae4dd`。本轮不合并、不部署。

## 诊断与改动

实际 spawned worker 的 cProfile 显示，100,000 条成交诊断运行中，成本敏感性约 7.61 秒、102 次检查点约 5.97 秒；累计时间包含嵌套，不能相加。这是带 profiler 的诊断值，不是普通运行延迟。成本敏感性原来执行四次完整双时钟循环，重复验序、聚合 K 线、决策记录和权益计算。

本轮实现两项：

1. **成本场景共享行情时钟**：仅对 Host 创建的精确类型双时钟克隆启用，一次验序和 K 线构造推进四个独立账户。每个账户仍独立处理订单、部分成交、费用、参与率、延迟、保证金及资金费；仍包含基线、费用 +25%、费用 +50%、延迟上调、参与率下调五个场景。场景结果只构造成本矩阵需要的 fills/ledger 和原哈希，主报告内容保持完整。
2. **按采样时刻构造权益点**：主双时钟循环在采样点才计算和构造权益记录，避免生成随即丢弃的记录。保留首点、周期采样、区间末点和恢复行为；每日收盘曲线仍逐事件更新。账户校验、资金费与逐笔撮合不跳过。

第一项复用成交内核新提取的 `_financial_result`，普通完整报告也使用同一财务构造函数。没有通过重写简化撮合模型获取速度，没有省略成本场景。

新增两个环境开关，默认 `1`；设为 `0` 分别恢复原路径：

- `BACKTEST_FUSED_DUAL_SENSITIVITY_ENABLED`
- `BACKTEST_LAZY_DUAL_CURVE_ENABLED`

本轮未改变检查点编码或 schema，第一轮的分块检查点回滚说明继续有效。

## 完整服务对照

保持第一轮三项开启，本轮只交替这两个开关。相同合成聚合成交、SMA 3/5、V2 撮合、每 1,000 条成交检查点；每对复制相同数据库和 run 身份，完整 result/report 必须相等。计时包含 worker、策略、撮合、成本矩阵、检查点和报告保存，不含数据生成、导入、HTTP 或浏览器。构建、测试和性能测量串行。

| 100,000 条行情、2,219 笔策略成交 | 上轮路径 | 本轮路径 | 耗时降幅 |
|---|---:|---:|---:|
| 配对 1 | 14.519 s | 10.630 s | 26.8% |
| 配对 2（先开启） | 12.614 s | 10.449 s | 17.2% |
| 配对 3 | 13.610 s | 11.165 s | 18.0% |

耗时中位数 **13.610 → 10.630 秒**。每对降幅中位数 **17.97%**；不将不同轮次的最好值拼成收益。所有完整 result/report 相等。证据：`performance-evidence-20260919/round2-final-dual-100k.json`。

`round2-dual-100k.json` 是仅合并成本场景时的阶段对照，其中第一对改善很小；保留该样本，不用最终结果覆盖它。

补充成交密集、信号较少的负载：每 100 条成交构成一根 K 线，仍为 100,000 条行情，产生 219 笔策略成交。三对原路径为 4.939 / 5.491 / 5.393 秒，开启为 3.155 / 3.105 / 3.978 秒；中位数 **5.393 → 3.155 秒**，配对降幅中位数 **36.12%**，全部完整结果与报告一致。证据：`round2-sparse-dual-100k.json`。

## 正确性边界

新增测试对照整份成本矩阵，包括所有场景财务哈希；覆盖基础及 V2 账户、费用、滑点、部分成交、IOC、OCO、止损限价、reduce-only、延迟、未成交订单、固定及历史资金费、辅助 mark 事件、空输入、数据缺口与预算拒绝。确认输入和主内核快照不被成本重跑修改。

权益曲线对照覆盖逐事件、每 7 条、每 1,000 条采样及每日模式，两个账户模型和检查点恢复。构造次数测试确认成本场景每条成交只进入一次 K 线构造器，五个场景仍全部存在。

本轮扩大回归 **258 passed**，0 failures / errors / skips，有 4 条既有 FastAPI deprecation warnings；Ruff 和 `git diff --check` 通过。证据：`performance-evidence-20260919/round2-regression.xml`，源码指纹与平台见 `round2-validation.json`。

## 剩余瓶颈

复查 profiler 后，完整双时钟循环从 5 次变为 1 次，成本敏感性在专用共享循环执行。诊断中成本部分约 3.67 秒；检查点仍需 102 次，约 9.31 秒，内置 SMA 的策略调用约 5.87 秒。该次 profiler 总时间反而比之前高，非改动部分也明显波动，所以只用它定位热点，不拿跨次 profiler 时间计算加速比例。

接下来值得处理的是检查点中尚未增量化的事件/决策等历史、反复 JSON 编解码，以及内置 SMA 信号输出时对全部历史 close 进行状态哈希。这些本轮没有修改；尤其状态哈希必须保持原契约，不能直接裁掉历史换取速度。诊断摘要保留为 `round2-profile-before.json` / `round2-profile-after.json`。

## 复现

在工作树根目录设置 `PYTHONPATH` 包含 backend 和两个 SDK 后：

```powershell
python -m scripts.benchmark_trade_strategy --round2 --events 100000 --pairs 3 --output output/trade-round2.json
python -m scripts.profile_trade_strategy --events 100000 --output output/trade-round2-profile.json
```

绝对耗时仅适用于此次 Windows 本地合成成交工作负载，不等同真实交易所数据或浏览器性能。逐笔策略回调模式未改为双时钟。本轮没有区间跳过、并行账户共享或策略信号降采样。
