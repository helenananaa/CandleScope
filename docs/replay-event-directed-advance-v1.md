# 事件导向推进：第一版

本版把区间筛查、保守执行和遇事件停止接入现有回放流程，不用高周期 OHLC 代替逐分钟成交规则。

后续已加入恒定风险与估值的持仓安全前缀、输入时间索引及账户事件游标对齐，见 [持仓安全前缀与 HEDGE 输入索引](replay-held-interval-certificates-v2.md)。下文是第一版范围和当时验证记录。

## 已实现

- BAR 候选区间建立 min(low)/max(high) 树，按时间先后查找固定限价、止损市价、止盈市价的最早可能触发位置。市场单直接进入精确执行。阈值判断包含等于边界的情形，并保留订单生效序号约束。
- 索引绑定不可变 BAR 对象；同时间戳换成另一批数据时不能复用。已构建索引的安全区间可用根节点排除，候选区间逐层向下查找。索引只做可能性判定，实际成交价格、滑点、可成交数量和拒单仍由原经纪商处理。
- 单轨 BAR/HEDGE、无持仓但有挂单、无历史盘口且非历史精确账户时，允许筛查后的安全前缀批量执行。候选事件在独立基础事件边界执行，成交后不继续跳过后续账户风险。
- 已知资金费、规则、费率等输入会切开安全前缀，边界本身按原顺序处理；不会为了区间快进跨过这些事件。
- `advance`/`step_display` 的展示周期按钮默认携带 `stop_on_event: true`；API 不携带该字段时仍保持原语义，传 false 可请求原来的完整目标推进。值必须是 boolean。
- 请求事件停止时，成交、订单状态变化、清算、账户输入事件或新增经纪商警告会在完整的当前事件边界落盘后结束本次推进。返回 `data.event_stop` 与 `target_reached`，前端显示“已在事件发生处暂停”。下一次推进从实际游标继续，已完成命令仍可幂等重试。
- 已有持仓的停止行为也支持；未证明安全时逐根执行到事件，不会为了提速跳过风险检查。

## 精度与边界

这不是通用的 O(log N) 日/周跳跃引擎。索引查询可以剪枝，但冻结数据第一次读取、索引构建、源事件哈希链、指标需要的序列和批量精确 reducer 仍有线性工作；目前索引缓存是有界候选窗口，不是整个归档的持久化分层摘要。

已有持仓的通用区间风险证明尚未完成。本版不会仅根据成交 K 线高低价推断多仓、空仓、资金费、标记价格、逐仓/全仓、组合保证金和路径指标都安全；这些情况保留原路径。当前主要收益是“等待固定价格订单”的长安全前缀，以及触发事件后不再继续推进到原目标。

仅有 1m OHLC 时，停止精度是现有基础事件粒度，不宣称知道真实秒级成交顺序。同一时间点的必要账户处理保持现有因果顺序。服务端筛查可以读取已冻结的未来数据，返回的 K 线与指标仍严格截断到实际停止游标，不向客户端暴露筛查区间的未来高低价。

## 验证场景

- 513 根随机 BAR、500 次任意子区间查询，与线性查找的首个触价位置一致。
- 4096 根全部安全的区间，建索引后一次根节点边界读取即可排除。
- BUY/SELL 的 LIMIT、STOP_MARKET、TAKE_PROFIT_MARKET 六种组合与原 `_trigger` 一致；同时间戳替换数据不使用旧索引。
- 挂限价单推进 4h，无触发时跨过超过 200 根分钟数据，适配器批次不超过 3；第 38 根分钟 K 首次触价时，在首次成交后停止。
- 资金费发生在目标内部时，在该边界停止，并与禁用批处理的参考执行对比。
- 已有持仓的止损保留逐根风控，并停在相同首次成交分钟。
- 安全前缀与逐根参考执行的最终账户组件、游标、state_hash 一致；停止结果的命令重试不重复推进。
- 单轨目标扫描路径也支持成交后停止，并验证重启后幂等返回。

前端已通过 396 项回放测试、TypeScript、相关 ESLint、9 语言 i18n 检查和生产构建。最终完整后端回放为 **1094 passed、3180 deselected**（4 条既有 FastAPI 警告），记录于 `output/replay-latency-sampling-20260909/interval-final-regression.log`。首次全量运行的旧断言要求资金费前首根使用非批量参数；已改为验证实际只前进一根，并保留资金费时间、审计与恢复检查，最终全量重跑通过。

## 整周样本

专用合成数据、单轨 HEDGE、无持仓且有未触及的 BUY LIMIT，价格整周保持在限价之上。从周一起点推进完整一周，结果为：10,080 个基础事件、20 个适配器批次、62 次写事务、约 **3974ms** 服务端推进时间，`target_reached=true`、`event_stop=null`。准备数据、建档和浏览器渲染不在这段时间内；这是一次样本，不能当作通用持仓延迟或长期分位数。

测试夹具默认容量只有 1000 行，初次尝试未成功进入推进；中间的大范围准备尝试也被中止。最终专用夹具使用固定窗口、20,000 行容量和 60 秒控制权租约，这些只属于测量进程，没有改动生产限制。证据为 `weekly-benchmark.json`、`weekly-benchmark-v4.log` 和 `benchmark_week.py`。保留此前失败/中止日志，不将准备阶段算入成功推进样本。

实际回放库备份后，本地后端已加载新实现，18080 健康检查返回 200；前端刷新后使用新的默认事件停止策略。
